# 探探使用教程：连接自己的电脑，继续自己的 Codex 会话

适用对象：准备通过钉钉「探探」操作自己电脑或服务器上 Codex 的用户。  
核对日期：2026 年 11 月 4 日。对应 Gateway 版本：a77300c。  
终端示例适用于 macOS / Linux；Windows 不属于本教程已核对的安装路径。

## 先看明白：探探和 Connector 各做什么

探探是钉钉里的消息入口，Connector 运行在你的电脑或服务器上。你在钉钉发出的任务，由自己设备上的 Codex 执行；进展、审批和结果通过探探回到钉钉。

你不需要搭建自己的机器人，也不需要把 Codex 的登录凭据交给探探管理员。你的设备需要保持开机、联网，Connector 需要持续运行。设备主动连接探探，不要求给自己的电脑开放入站端口。

**第一次使用优先私聊探探。** 一个群里只有一份当前会话绑定，多人可以切换它；并不是每个人在同一个群中各自绑定一个会话。详见「多人群聊」一节。

## 一、开始前准备什么

### 你自己准备

- Git、Node.js 和 npm。项目支持 Node.js 22.13 及以上的 22.x，或 23.4 及以上版本。
- 能正常工作的本机 Codex：已经完成你自己的登录或模型配置，能在目标项目中使用。
- 能访问探探的网络。当前入口是内网地址，不是任意公网环境都能直接访问；需要处于获准的内网或相应 VPN 中。
- 能打开交互式终端。第一次配对需要在设备端核对申请并输入确认，不能一开始就完全无交互地放到后台。

只安装 Codex CLI、没有 Codex 桌面 App 的 Linux 服务器也可以接入。本教程使用独立原生 App Server 的 daemon 连接方式。

### 向探探管理员领取

| 材料或设置 | 用途 |
| --- | --- |
| 探探机器人入口 | 在钉钉找到正确的机器人并发起私聊 |
| 本人的使用准入 | 允许你的钉钉账号使用探探；有机器人入口不代表已获准 |
| 独立的设备 ID | 配置中的 nodeId，每台设备单独登记 |
| 设备令牌文件 | 例如 device.token；管理员须在服务器登记相同设备凭据 |
| Gateway CA 证书文件 | 例如 gateway-ca.pem，用于校验当前内网 HTTPS/WSS 证书 |
| 连接配置与客户端版本 | 以管理员交付的 peer-client.json 和匹配版本为准 |

**设备令牌不能与别人共用，也不要发到钉钉群、提交到 Git 或放进文档。** 请通过管理员指定的安全方式交付文件。CA 证书是用于验证服务身份的公开证书，不是设备令牌。

当前探探 Connector 入口为 wss://11.158.199.29:49186/gateway/v1/peer。这是 Connector 连接地址，不是浏览器 IDE 地址。

## 二、安装 Connector

如果管理员已经给你准备好的客户端目录，可以直接进入下一节。以下为从源码安装的方法，每个代码块是一条可执行命令，按顺序执行。

下载项目：

```sh
git clone https://github.com/yanjijinxiao/codex-im-gateway.git
```

进入目录：

```sh
cd codex-im-gateway
```

本教程对应以下版本；如果管理员提供了更新的配套版本，使用管理员指定版本：

```sh
git checkout a77300c9092465640806f1a9a517b15ea9fa4373
```

安装依赖：

```sh
npm ci
```

构建 Connector 所需程序：

```sh
npm run build:bridge
```

不需要在自己的电脑启动另一套探探 Gateway，也不需要配置钉钉机器人 AppKey/AppSecret。

## 三、放好本机配置

创建一个稳定的配置目录：

```sh
mkdir -p "$HOME/.config/tantan-connector"
```

把管理员交付的 peer-client.json、device.token 和 gateway-ca.pem 放在该目录。不要把 device.token 放到代码仓库里。

下面是 **peer-client.json 配置模板，必须修改设备 ID 和设备名称后再保存**。设备 ID 必须与管理员登记的一致；如果管理员已经交付完整配置，优先使用该文件。

```json
{
  "url": "wss://11.158.199.29:49186/gateway/v1/peer",
  "nodeId": "替换为管理员分配的设备ID",
  "label": "替换为你的设备名称",
  "tokenFile": "./device.token",
  "caFile": "./gateway-ca.pem",
  "profileId": "default",
  "backend": "app-server",
  "appServerTransport": "daemon",
  "codexBin": "codex",
  "stateDir": "./state",
  "webIDE": {
    "enabled": false,
    "binary": "code-server",
    "autoInstall": false
  }
}
```

这里的相对路径均相对于 peer-client.json 所在目录。stateDir 保存配对授权和执行回执，升级时要保留，不要让两个 Connector 同时使用它。

其他配置说明：

- label 只是设备显示名称，不是钉钉用户 ID。
- profileId 是本次连接资源的标识，不是 Codex CLI 的配置 profile 名；设置好后保持稳定。
- 不需要填写自己的钉钉用户 ID，也不需要提前填写 session ID。你的钉钉身份在实际配对时确定。
- 默认可以选择该本地 Codex 资源下的普通会话。若管理员要求仅开放指定会话，可使用受限配置；不要自行添加其他人的 threadId。
- 如果 Codex 不在 PATH 中，请让管理员把 codexBin 改成正确的可执行文件路径。
- 如果使用非默认 Codex 数据目录，可以配置 codexHome。请填写绝对路径或相对于配置文件的路径，不能把 JSON 中的 `~` 当作 shell 自动展开。

检查本机 Codex 命令是否可用：

```sh
codex --version
```

检查本机版本是否提供所需 daemon 子命令：

```sh
codex app-server daemon --help
```

如果不支持，先让管理员核对本机 Codex 版本和路径；不要为绕过错误随意切换成 stdio。Connector 会按配置启动或连接独立 daemon，不需要你手写 socket 地址。

如果你已有 Codex 桌面 App，应使用同一个系统用户和正确的数据目录，并让管理员核对桌面与 Connector 是否连接同一个原生服务。仅仅“电脑上只有一个 App 窗口”不能证明执行服务一致；不要靠清理锁文件处理会话占用。

## 四、启动并配对

在刚才的 codex-im-gateway 项目目录里执行：

```sh
npm run peer -- --config "$HOME/.config/tantan-connector/peer-client.json"
```

连接成功后，终端会显示设备名称，以及一条带配对码的完整 /connect 命令。

1. 保持这个终端运行。
2. 把终端给出的 **完整命令** 发给钉钉里的探探。私聊可以直接发送；群里先从成员列表真正 @探探，再发送命令。
3. 回到设备终端，核对申请人的身份、机器人账号、聊天和开放范围。
4. 确认是你发起的申请后，在这个设备终端输入：

```text
yes
```

5. 探探确认配对成功后，会显示这台设备的会话列表；选择你要继续的会话。

如果需要手动理解命令形式，下面仅为 **需要替换的模板**，不能原样使用：

```text
/connect <终端显示的实际配对码>
```

配对码有效期为 5 分钟，一次使用后即失效；申请发起后要及时回终端确认。过期、拒绝或设备重连后，使用终端新显示的命令。

**配对码不是通过 curl 获取的。** Connector 先用独立设备凭据建立连接，再由探探返回短期配对码。设备令牌、配对码和设备端确认是不同的步骤。

首次配对后可以继续前台运行。若需要开机自动运行，可让管理员配置系统服务；本教程的启动命令不会自动安装后台服务。未配对前直接用无交互后台方式启动，设备端不会自动批准申请。

## 五、选择会话，开始工作

### 查看自己在当前聊天已配对的设备

```text
/connect
```

这里只显示你在当前机器人、当前聊天中已获授权的设备，不是全部在线机器。换到另一个群或私聊，不会自动继承原聊天的设备授权，需要在新聊天重新配对。

### 查看会话

```text
/sessions
```

会话目录按「置顶 → 项目与其会话 → 其他会话」组织，保留没有未归档会话的项目。多设备时，优先从 /connect 返回的设备入口选择来源。

选择列表中的按钮即可绑定。也可以发送下面的 **示例命令**；R1 必须确实是你刚看到的目标会话，编号以当前列表为准：

```text
/session R1
```

查询当前绑定位置：

```text
/status
```

核对设备、项目和会话无误后，直接发送自然语言任务即可。第一次可以只要求它报告当前工作目录，确认执行位置后再进行修改。

### 在项目中新建会话

先查看设备上的原生项目：

```text
/project
```

按返回的真实项目编号选择。以下为 **示例命令**，C1 必须是列表中你的目标项目：

```text
/new C1
```

已经选中项目时，可以使用：

```text
/new
```

创建会话本身不提交模型任务，下一条普通消息才开始执行。不要仅凭目录存在就认为它已登记为原生项目；空项目列表需要先在设备端核对项目。

若只想创建无项目的独立会话，在确认当前设备后使用：

```text
/new --standalone
```

独立会话使用设备上的持久工作目录，但不自动拥有项目 Web IDE 入口。没有选定设备时不要盲目执行；先通过 /connect 或 /sessions 确认来源。

## 六、日常使用

### 连续发送长需求或多份附件

开始合并：

```text
/prompt start
```

然后连续发送文字、图片或文件，准备好后统一提交：

```text
/prompt done
```

取消尚未提交的合并内容：

```text
/prompt cancel
```

/prompt 是消息合并功能，不是查看系统提示词的命令。取消合并不会停止已经交给 Codex 的任务。多人群聊不宜交叉使用同一个合并区。

### 任务运行时追加要求

默认情况下，普通追加消息会介入当前轮次。想让内容在下一轮执行，可使用原生队列；以下是 **需要替换正文的模板**：

```text
/queue <下一轮要执行的完整要求>
```

队列能力需要设备端原生服务支持。使用 /status 和实际回执确认是否已提交，不要根据机器人暂时没回复就重复发送。

### 常用查询

| 命令 | 用途 |
| --- | --- |
| /help | 查看帮助 |
| /help session | 查看会话相关帮助 |
| /status | 核对当前绑定和状态 |
| /sessions | 查看会话目录 |
| /sessions more | 会话目录下一页 |
| /history 10 | 查看最近对话 |
| /history more | 查看更早的历史 |
| /inbox | 核对待转发和提交回执 |
| /queue list | 查看本聊天的队列回执 |
| /role | 查看自己在当前聊天的角色 |
| /access | 查询本人和当前聊天的准入情况 |

### 审批和补充问题

需要工具审批或补充信息时，以探探发送的实际卡片为准，直接使用按钮，或发送卡片提供的完整命令。不要照抄别人的审批编号，也不要把“复制命令”误认为“已经批准”。

审批、停止任务等控制操作需要相应聊天角色；设备端 Codex 原本的沙箱与审批策略仍然有效，Connector 不会因为配对而取消它们。

### 停止任务与退出绑定

确实要中断当前任务时使用（需要 controller 权限）：

```text
/stop
```

只想让这个聊天不再绑定当前会话时使用：

```text
/unbind
```

/leave 是 /unbind 的兼容命令。解绑不会删除原生会话、停止原任务、取消原生队列，也不会撤销这台设备的配对授权。解绑后要先重新选择会话，才能继续发任务。

## 七、多人在同一个群里会怎样

**同一个群共用一份当前绑定。不是“每个群成员各有一份”，也不是“谁先绑定谁独占”。**

例如：甲把群绑定到自己的会话 A，乙也已经获准使用探探，并在这个群完成自己设备的配对。按当前实现，乙可以切换到自己的会话 B，也可以先解绑再绑定。切换会改变整个群后续普通消息的去向；甲的会话 A 不会因此被停止，但这个群不再跟随原绑定。

当前普通参与者权限即可执行常规解绑和切换，不需要取得首次绑定者的额外同意。个人准入用户默认有 controller 权限；显式设置的个人聊天角色优先。资源共享访客另有用于进入/退出已授权资源的绑定路径，因此不要把聊天角色当作“绑定所有者锁”。

设备访问仍按具体用户、聊天、机器人和设备校验：乙能切到自己的机器，不代表乙因此取得甲机器的权限。不过，已经发到群里的回复和历史，群成员都能看见。

使用方式建议：

- 每个人独立操作自己的机器：分别私聊探探。
- 每个人需要多个独立工作上下文：分别使用专用群。
- 多人共同操作同一个任务：使用协作群，并先约定谁切换绑定、谁审批和停止任务。

如果你需要“只有绑定者或指定管理员才能解绑/切换”，当前实现不能作这个保证，需要另行增加这项规则。

## 八、Web IDE：可选功能，需管理员为设备开通

完整 Web IDE 提供文件编辑、Git 和终端。它与聊天接入是两个步骤，**配对成功不等于 IDE 已经开通**。

使用条件：

1. Connector 显式启用完整 IDE，设备上的 code-server 可用。
2. 管理员在探探的 IDE 设置中启用该 peer 主机，并配置可访问的 HTTPS 入口。
3. 当前绑定的是具有已核对原生项目归属的会话。
4. 当前访问来源满足该设备的完整 IDE 授权。

上面的完整配置默认关闭 IDE。如果管理员为设备开通自动安装，请编辑原 peer-client.json 中的 webIDE 配置：

| 配置项 | 开通自动安装时的值 |
| --- | --- |
| webIDE.enabled | true |
| webIDE.binary | code-server |
| webIDE.autoInstall | true |

保留其他配置，并与管理员确认版本和设备环境。也可以由管理员预装 code-server，然后把 binary 配成正确的绝对路径、autoInstall 设为 false。自动安装会校验固定制品；Linux 需要 glibc ≥ 2.28，其他不支持的平台不会自动修改系统运行库来绕过。

配置完成后重启 Connector。在钉钉选择项目会话后获取入口：

```text
/ide
```

使用返回的固定项目链接，不要把 WSS 连接地址当作 IDE 地址。

### 当前探探的直接进入策略

已经启用链接直达的项目，新浏览器点击链接后会自动进入并信任目录，无需发本人确认码，也不使用钉钉免登。**持有这种链接的人可以使用对应 IDE 的文件、Git、终端，请按开发访问凭证保管链接。** 有效期最长 90 天，策略到期或被撤销后不自动续期。

但当前实现是 **每个机器人账号一条固定授权来源**，不是为每个新用户自动分别生成一条来源。新增用户的 Connector，如果没有对应来源的有效设备授权，不能直接套用现有策略；管理员应先核对并验收，不能承诺“任何人配对后都能免确认打开自己的 IDE”。

因此，本教程可以用于开通新用户的 Connector 聊天与任务执行；新用户的完整 IDE 应单独标记为「管理员开通并验收后可用」。不要为了开通 IDE，把另一位用户的整台设备权限随意授予现有授权来源账号。

只获会话共享文本权限的访客可能看到的是「共享 Web 编辑器」，它不提供完整 Git/终端，且可能仍需要自己的浏览器确认；不要与上述完整 IDE 混为一谈。

## 九、常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 探探提示尚未获准 | 联系管理员开通本人准入。原消息未提交，获准后重新发送原请求 |
| /connect 没有设备 | 是否在已经配对的那个聊天中？第一次使用需先启动 Connector |
| 一直连接不上或反复重连 | 内网/VPN、入口、nodeId、设备令牌、CA 文件是否正确；让管理员核对服务端设备登记 |
| TLS/证书错误 | 获取管理员更新的证书文件、检查时间和证书期限；不要用关闭证书验证的方法处理 |
| 配对码过期或已使用 | 使用 Connector 最新显示的完整配对命令；必要时重启 Connector 获取新码 |
| 终端没有办法确认或被拒绝 | 首次是否在交互式终端运行？是否及时输入了 yes？申请人和聊天是否正确？ |
| 列表里没有自己的会话 | 核对设备来源、系统用户、codexHome、会话是否归档；在设备端确认 Codex 能看到它 |
| 提示会话在其他应用中打开 | 核对桌面 App 与 Connector 是否连接同一原生服务；不要删锁或另起执行器强抢 |
| 新消息提示已保存、尚未提交 | 看 /inbox 和 /status，检查 Connector 与原生服务；不要连续重发 |
| /ide 没有入口 | 检查是否为原生项目会话、设备是否启用完整 IDE、Gateway 是否启用对应主机 |
| IDE 提示链接不可用 | 让管理员检查期限、项目归属和授权来源是否匹配该设备；重复刷新不会获得权限 |
| 同群消息去了另一个会话 | 查看 /status，可能是其他成员切换了群的共享绑定 |

### 重启、离线和升级

Gateway 重启后会按持久绑定、输入回执和原生轮次恢复连接；已经由独立 Codex 服务接收的任务不应因为单独重启 Gateway 而被重新执行。

Connector 使用本教程的 daemon 方式时，原生执行服务独立于 Connector；断线重连不是重新提交任务。**这不代表电脑关机、原生服务退出或 IDE 终端重启也能保证任务继续。** 显式 stdio 模式的生命周期不同，不适用独立执行保证。

升级时保留设备凭据、stateDir 和 Codex 数据目录。不要删除回执文件“清除卡住状态”，否则会破坏已提交消息的核对依据。需要撤销设备访问时，联系管理员处理；/unbind 只改变聊天绑定。

## 附录：管理员发给新用户前的检查

1. 开通准确的个人准入，不把「加入了某个群」误当作已经开通个人设备访问。
2. 每台设备生成独立凭据并登记服务端 nodeId/tokenFile，安全交付匹配的客户端配置。令牌不嵌入本教程，也不放聊天或公开下载链接。
3. 确认用户能够到达内网 WSS 入口；不要给用户开放 Gateway 本机管理接口。当前管理 UI 不是按钉钉身份隔离的多人门户。
4. 确认本机 Codex 的版本、数据目录和原生服务连接一致，再配对；设备配对不是新增模型账号。
5. 第一次配对必须让用户在自己设备上确认实际聊天与身份，随后从钉钉绑定自己的会话。
6. 做一次只读往返：核对工作目录、历史和进展；不要把收到「已连接」当作任务执行已经验收。
7. 需要 IDE 时，单独检查设备开关、Gateway 主机设置、原生项目归属和浏览器授权来源，并用新浏览器实际打开。当前账号级固定来源尚不等于多用户自动直达。
8. 说明群绑定共享规则；不要向使用者承诺「首次绑定者独占」。
