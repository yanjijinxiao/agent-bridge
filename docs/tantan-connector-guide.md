# 探探使用指南：连接自己的设备，在钉钉使用 Codex

探探让你在钉钉里继续自己电脑或服务器上的 Codex 会话。你发送需求、图片或文件，Codex 在所选设备上执行，探探把进展、审批和结果发回原聊天。

你只需在自己的设备运行 Connector，再与探探配对。设备主动连接探探，无需开放入站端口，也无需自己部署机器人。

本文的终端命令适用于 macOS 和 Linux。只有 Codex CLI、没有桌面 App 的服务器也可以接入。

## 1. 可以用探探做什么

| 你想做的事 | 使用方式 |
| --- | --- |
| 继续已有任务 | 配对设备，选择已有会话，然后直接发需求 |
| 在项目里开始新任务 | 查看项目，在选定项目中新建会话 |
| 连续补充要求 | 任务运行时继续发消息，默认追加到当前轮次 |
| 把下一件事排在后面 | 使用 /queue 提交下一轮要求 |
| 合并长需求和多份附件 | 使用 /prompt 收集消息，再一次提交 |
| 处理审批、回答补充问题 | 使用实际卡片上的按钮或完整回复命令 |
| 在浏览器查看或修改项目 | 开通 Web IDE 后使用文件编辑、Git 和终端 |
| 在多台设备间切换 | 从 /connect 选择已配对设备，再选择会话 |

**建议第一次使用先私聊探探。** 同一个群共用一份当前会话绑定；如果希望每个人互不影响，使用私聊或不同的专用群。

## 2. 准备并安装 Connector

### 准备自己的设备

- 已安装且能正常使用 Codex，完成自己的登录或模型配置。
- 已安装 Git、Node.js 和 npm，Node.js 满足项目 package.json 中的运行要求。
- 设备能够访问管理员提供的探探入口；内网部署需要相应内网或 VPN。
- 首次启动使用交互式终端，方便核对并确认配对申请。

### 向管理员领取接入材料

| 材料 | 用途 |
| --- | --- |
| 探探机器人入口与本人的使用准入 | 能找到探探，并允许你的钉钉账号使用它 |
| peer-client.json | 连接配置，包含入口和这台设备的标识 |
| device.token | 这台设备的独立连接凭据 |
| gateway-ca.pem（使用内部 CA 时） | 验证探探连接入口的证书 |

配置和凭据应通过管理员指定的安全方式交付。不要把 device.token 发到群里、交给其他使用者或提交到代码仓库。Codex 的登录凭据留在自己的设备上。

### 下载和构建

如果管理员已提供构建好的 Connector 目录，直接使用该目录，跳到“放好配置”。从源码安装时，依次执行以下命令。

下载项目：

```sh
git clone https://github.com/yanjijinxiao/codex-im-gateway.git
```

进入项目目录：

```sh
cd codex-im-gateway
```

安装依赖：

```sh
npm ci
```

构建程序：

```sh
npm run build:bridge
```

安装完成后，后面的启动命令都在这个项目目录执行。无需启动另一套 Gateway，也无需配置机器人 AppKey 或 AppSecret。

### 放好配置

创建用于保存连接配置和状态的目录：

```sh
mkdir -p "$HOME/.config/tantan-connector"
```

把管理员提供的 peer-client.json、device.token 和需要的 gateway-ca.pem 放进去。如果文件名不同，以配置实际指向的文件为准。

管理员已经提供完整配置时，不需要自己重写。需要手工填写时，可使用下面的 **peer-client.json 模板，先替换入口、设备 ID 和设备名称，再保存到上述目录**。入口使用管理员提供的 WSS 地址；设备 ID 须与服务端登记一致。

```json
{
  "url": "wss://替换为探探连接入口/gateway/v1/peer",
  "nodeId": "替换为这台设备的ID",
  "label": "替换为便于识别的设备名称",
  "tokenFile": "./device.token",
  "caFile": "./gateway-ca.pem",
  "profileId": "default",
  "backend": "app-server",
  "appServerTransport": "daemon",
  "codexBin": "codex",
  "stateDir": "./state",
  "webIDE": {
    "enabled": false,
    "binary": "code-server",
    "autoInstall": false
  }
}
```

使用系统已经信任的证书且管理员未提供 CA 文件时，删除 caFile 这一项。

几个容易混淆的配置：

| 配置 | 如何理解 |
| --- | --- |
| url | Connector 连接入口，不能拿它当作浏览器 IDE 地址 |
| nodeId | 设备的登记标识，每台设备独立配置 |
| label | 设备显示名称，不是钉钉用户 ID |
| profileId | 连接资源的标识，设置后保持稳定，不是 Codex CLI 的配置 profile 名 |
| codexBin | Codex 可执行命令；不在 PATH 中时填写正确的绝对路径 |
| stateDir | 配对授权和执行回执的保存位置，更新程序时保留 |
| webIDE | 可选浏览器 IDE 的开关，开通方法见第 7 节 |

文件及数据目录的相对路径按 peer-client.json 所在目录解析。若使用非默认 Codex 数据目录，可增加 codexHome，并填写正确路径；JSON 中的 `~` 不会自动展开。不要让两个 Connector 进程同时使用同一个 stateDir。

不需要在配置里填写钉钉用户 ID 或 session ID：你的身份在配对时确认，会话在钉钉里选择。

### 检查 Codex

先确认终端能找到 Codex：

```sh
codex --version
```

再确认它支持 Connector 使用的原生服务入口：

```sh
codex app-server daemon --help
```

若命令不可用，先核对 Codex 安装和可执行路径。已有 Codex 桌面 App 时，应使用相同系统用户及正确的数据目录，并确认桌面与 Connector 连接同一个原生服务，避免两个执行器争用同一会话。

## 3. 启动设备连接，完成第一次配对

在 Connector 的项目目录执行：

```sh
npm run peer -- --config "$HOME/.config/tantan-connector/peer-client.json"
```

连接成功后，终端会显示设备名称和一条带配对码的完整命令。

1. 保持终端运行，把它显示的 **完整 /connect 命令** 发给探探。
2. 私聊可以直接发送；在群里需要从成员列表真正 @探探，再发送命令。
3. 回到设备终端，核对申请人、机器人、聊天和开放范围。
4. 确认是你的申请后，在设备终端输入下面的回答。

```text
yes
```

5. 探探确认配对成功后，会直接显示该设备的会话目录，选择要继续的会话即可。

配对码有效期为 5 分钟，一次使用后失效。过期或被拒绝时，使用终端新显示的命令；必要时重启 Connector 获取新码。配对码由连接成功后的服务交互产生，不需要另外执行 curl 获取。

**配对针对具体用户、机器人和聊天。** 换到另一个群或私聊，需要在那里完成配对；不会因为知道设备名称就获得访问权。首次配对要在设备终端确认，非交互式后台启动不会自动同意申请。

完成配对后，Connector 仍需持续运行。退出终端或按 Ctrl-C 会停止这个前台 Connector；需要开机自动运行时，可由管理员配置系统服务。

## 4. 选择设备、项目与会话

### 选择已有会话

查看自己在当前聊天有权使用的设备：

```text
/connect
```

选择设备入口，再从返回的目录选择会话。以后也可以直接刷新会话目录：

```text
/sessions
```

目录按“置顶 → 项目及其会话 → 其他会话”组织，没有未归档会话的项目也会保留。直接点选择按钮即可；需要文字命令时，使用目录给出的完整命令和实际编号。

选好后，核对当前设备、会话和工作目录：

```text
/status
```

然后直接发送自然语言，例如：请检查这个项目的登录流程，先说明现状，再修改问题并验证。

多设备时，先从 /connect 选择来源，避免把任务发到另一台设备。设备上的会话由 Codex 管理，Connector 不要求你为每个会话重写配置。

### 在项目中新建会话

查看设备上的项目：

```text
/project
```

从返回的真实项目中选择，并使用对应的新建入口。文字命令的 **模板如下，执行前把项目编号替换成列表中的实际编号**：

```text
/new <项目编号>
```

已经选定项目时，可以直接新建：

```text
/new
```

创建会话只建立工作上下文，下一条普通消息才开始执行任务。

需要无项目的独立会话时，先确认目标设备，再发送：

```text
/new --standalone
```

无项目会话不自动获得项目 Web IDE。项目列表为空时，应先在设备端核对项目登记，不能仅凭磁盘上存在某个文件夹就认为它已是可选项目。

## 5. 发送需求、附件与后续任务

### 普通消息与附件

绑定会话后，直接发送文字、图片或文件，并说明希望 Codex 如何处理。附件会传到所选设备；Codex 返回的文件通过探探发送到聊天。

任务运行时发送普通补充消息，默认会追加到当前轮次。若这个会话配置了不同的消息策略，以实际回执为准。

### 把多条消息合并成一次需求

开始收集：

```text
/prompt start
```

接着连续发送文字和附件，全部准备好后提交：

```text
/prompt done
```

放弃尚未提交的内容：

```text
/prompt cancel
```

/prompt 用于合并消息，不是查看系统提示词。取消收集不会停止已经提交的任务；多人群聊应避免交叉使用同一个收集区。

### 让下一件事排在后面执行

使用下面的 **命令模板，把占位文字替换为完整任务要求**：

```text
/queue <下一轮要执行的完整要求>
```

队列由设备上的 Codex 原生服务管理，需要该服务支持相应能力。查看当前聊天的队列回执：

```text
/queue list
```

探探暂时没有回复、显示断线或回执待确认时，可查看消息交接情况：

```text
/inbox
```

已经接收的输入、结果不明的提交，不会因为重连就自动重复提交。先看实际回执，不要连续重发同一个任务。

## 6. 进度、审批与任务控制

任务执行时，探探会更新 AI 卡中的状态、进展和工具信息。需要审批或补充回答时，使用实际卡片上的按钮；如果卡片提供文字回复方式，发送其中的完整命令。

**点击复制只复制内容，不会提交答案或批准操作。** 审批成功后，后续进展会继续展示。设备上 Codex 的沙箱和审批规则仍然有效。

| 看到的状态 | 如何处理 |
| --- | --- |
| 进行中 | 可以等待，或继续补充要求 |
| 等待审批 / 等你回答 | 处理对应卡片里的请求 |
| 执行状态待确认 | 用 /status 和 /inbox 核对连接及回执，不把它当作任务失败或仍在执行的证明 |
| 已完成 / 执行失败 / 已中断 | 阅读最终结果或失败原因，按需要发起下一步 |

确实要中断当前任务时发送：

```text
/stop
```

停止任务及审批等控制操作需要相应聊天角色。/stop 作用于当前绑定任务，不用于清理旧卡片或恢复网络。

只想解除当前聊天的会话绑定时发送：

```text
/unbind
```

/leave 也可用于解绑。解绑不会删除会话、停止原任务、取消原生队列或撤销设备配对；之后需重新选择会话才能继续发任务。

其他常用查询：

| 命令 | 用途 |
| --- | --- |
| /help | 查看帮助与可用功能 |
| /help session | 查看会话操作帮助 |
| /sessions more | 查看下一页会话 |
| /history 10 | 查看最近对话 |
| /history more | 查看更早的对话 |
| /role | 查看自己在当前聊天的角色 |
| /access | 查看本人在当前聊天的准入情况 |

## 7. 用 Web IDE 查看、编辑项目

完整 Web IDE 提供文件编辑、Git 和终端，适用于已开通的本机、远程或 Connector 项目。只有 CLI 的服务器也可以使用，不需要安装桌面图形界面。

### 开通一次，以后从项目链接进入

管理员需要在探探侧启用你的设备 IDE，并配置可访问的 HTTPS 入口；设备端也要开启 webIDE。配对聊天本身不会自动完成这一步。

要让 Connector 自动准备 code-server，在原 peer-client.json 中设置：

| 配置项 | 设置值 |
| --- | --- |
| webIDE.enabled | true |
| webIDE.binary | code-server |
| webIDE.autoInstall | true |

保留其他配置，保存后重新启动 Connector。首次打开 IDE 时，设备会检查环境，缺少 code-server 时下载、校验并安装，**无需用户另外手动安装 code-server**。这要求设备能够获取安装包且系统受支持；自动安装覆盖 macOS Intel / Apple Silicon 和 Linux x64 / ARM64，Linux 还需满足运行库要求。不支持的环境会明确报错。

设备已装好 code-server 时，也可把 binary 填为其绝对路径，并关闭 autoInstall。

### 打开 IDE

在钉钉绑定一个项目会话后，发送：

```text
/ide
```

打开返回的项目链接即可。已有入口也会显示在对应的进行中卡片和最终回复中，同一个项目使用同一个固定链接。无项目会话不自动产生 IDE 入口。

浏览器中的文件、Git 和终端运行在项目所在设备上。设备离线时，这些功能也无法继续使用。

### 第一次打开为什么可能需要确认

访问方式由管理员为项目配置：

- **个人浏览器确认**：首次按页面完成本人确认，之后在有效期内直接进入；不需要再设置一套 IDE 密码。
- **持链接直接进入**：已开通的项目无需填写确认码，点击后直接进入并信任目录。链接具有项目开发访问能力，应只发给允许访问的人。

浏览器授权最长 90 天，到期或撤销后需要重新建立访问资格。

目前“持链接直接进入”按机器人账号配置授权来源。新用户配对成功，并不自动保证其设备也能直达 IDE；管理员仍需核对该来源是否有目标设备权限，再为该用户开通。遇到确认页或拒绝访问时，交由管理员核对，不能用其他人的设备授权代替。

仅获得文本共享权限的人可能看到“共享 Web 编辑器”，它不提供完整 Git 和终端。

## 8. 多人群聊怎么用

**一个群只有一份当前会话绑定，群成员不是各自拥有一份绑定。**

例如：甲把群绑定到自己的会话 A；乙也获准使用探探，并在这个群配对了自己的设备。乙可以把群切换到自己的会话 B，也可以先解绑再绑定。之后群里的普通任务会发往 B，A 的任务不会因此停止。

按当前权限规则，已准入的普通参与者可以执行常规解绑和切换，不必取得首次绑定者的额外同意。个人设备访问仍需分别授权：乙能切换到自己的设备，不代表乙就有权操作甲的设备。

- 各自独立做事：分别私聊探探，或各用一个专用群。
- 共同处理一个任务：使用协作群，事先约定由谁切换会话、审批和停止任务。
- 不确定任务发往哪里：先查看 /status。

群里已经发出的结果和文件对群成员可见。当前没有“首次绑定者独占”规则。

## 9. 常见问题与恢复

| 现象 | 处理方法 |
| --- | --- |
| 探探提示尚未获准 | 联系管理员开通本人准入；确认原消息未提交后再发送需求 |
| /connect 没有设备 | 首次先启动 Connector 并配对；也要确认是否换了聊天 |
| 连接失败或不断重连 | 核对网络/VPN、入口、设备 ID、令牌文件和证书；由管理员检查设备登记 |
| 证书错误 | 核对设备时间并向管理员获取正确证书，不要关闭证书校验 |
| 配对码过期或被拒绝 | 使用终端新显示的完整命令，并及时回设备确认 |
| 后台启动却不能确认申请 | 首次改用交互式终端，核对身份后输入 yes |
| 看不到自己的项目或会话 | 核对选中的设备、系统用户、Codex 数据目录和归档情况 |
| 会话提示被其他应用占用 | 核对桌面与 Connector 是否连接同一个原生服务，不要删除锁文件强抢 |
| 消息显示已保存、尚未提交 | 查看 /inbox 和 /status，恢复连接后核对，不要重复发送 |
| 任务已结束，旧卡片还显示停止入口 | 这是展示异常；不要用旧卡片的 /stop 清理，反馈给管理员核对 |
| /ide 没有入口 | 检查是否绑定项目会话，以及设备与探探两侧是否开通 IDE |
| IDE 安装失败 | 查看页面提示，由管理员检查下载网络、系统支持和安装状态后重试 |
| IDE 链接不可用 | 检查网络、授权期限、项目归属和设备权限 |
| 同群消息去了别人的会话 | 查看 /status，可能有成员切换了群的共享绑定 |

### 断线或重启后

设备保持开机和联网，Connector 会尝试重连。单独重启 Gateway 时，已由独立 Codex 服务接收的任务继续由该服务执行，Gateway 恢复后重新同步状态，不重新提交原输入。

本教程使用 daemon 连接，原生执行服务独立于 Connector。电脑关机或原生服务本身退出则是另一种情况，不能承诺任务继续。Connector 重启也可能断开浏览器 IDE 和其中的终端，操作前保存编辑内容。

### 更新 Connector

需要更新程序时，在停止 Connector 后更新源码或替换程序目录；源码安装重新执行第 2 节的依赖安装和构建，再用原配置启动。若源码目录存在自己的修改，先保存并处理合并，不能直接覆盖。

**保留 peer-client.json、设备凭据、CA 文件、stateDir 和 Codex 数据目录。** 不要通过删除配对或执行回执来“清除卡住状态”；更新程序也不要求重新创建原有会话。

## 10. 管理员交付时需要准备什么

给新使用者交付时，完成以下事项即可让对方按本文接入：

1. 提供探探入口、开通准确的个人准入，并说明所需网络。
2. 为每台设备登记独立凭据，交付完整配置、令牌文件及需要的 CA 证书。
3. 指导用户在自己的交互式终端确认配对，并在钉钉选择自己的会话。
4. 完成一次实际往返，核对执行设备、工作目录、进展和最终结果。
5. 需要 IDE 时，为该设备开通完整 IDE，核对项目及访问权限，并实际打开链接确认文件、Git 和终端可用。
6. 说明群聊共享绑定规则，以及如何查询状态、解绑和联系管理员。

Gateway 本机 Web 管理页是管理员控制台，不是供所有探探用户登录的门户。用户日常通过钉钉和获准的项目 IDE 操作即可。
