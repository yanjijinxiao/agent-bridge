# 探探使用指南：连接自己的设备，在钉钉使用 Codex

探探让你在钉钉里继续自己电脑或服务器上的 Codex 会话。你发送需求、图片或文件，Codex 在所选设备上执行，探探把进展、审批和结果发回原聊天。

本文用于接入已经运行的「探探」Gateway。你只需在自己的设备运行 Connector，再与探探配对。设备主动连接探探，无需开放入站端口，也无需自己部署机器人。

本文的终端命令适用于 macOS 和 Linux。只有 Codex CLI、没有桌面 App 的服务器也可以接入。

一个 Connector 可以同时访问本机和该 Codex 数据目录中已登记的远端主机，不必为每台远端再安装 Connector。探探只转发消息；项目、会话、执行、附件和 IDE 始终跟随你选中的实际主机。

如果你只访问别人分享的会话，不需要安装自己的 Connector；请直接看第 8 节，由会话提供者批准访问。

## 1. 可以用探探做什么

| 你想做的事 | 使用方式 |
| --- | --- |
| 继续已有任务 | 配对设备，选择已有会话，然后直接发需求 |
| 在项目里开始新任务 | 查看项目，在选定项目中新建会话 |
| 连续补充要求 | 任务运行时继续发消息，默认追加到当前轮次 |
| 把下一件事排在后面 | 使用 /queue 提交下一轮要求 |
| 合并长需求和多份附件 | 使用 /prompt 收集消息，再一次提交 |
| 处理审批、回答补充问题 | 使用实际卡片上的按钮或完整回复命令 |
| 在浏览器查看或修改项目 | 开通 Web IDE 后使用文件编辑、Git 和终端 |
| 在多台设备间切换 | 从 /connect 选择已配对设备，再选择会话 |
| 让别人使用自己提供的会话 | 确认会话所有权，发出邀请，由自己批准访问申请 |

**建议第一次使用先私聊探探。** 同一个群共用一份当前会话绑定；如果希望每个人互不影响，使用私聊或不同的专用群。

## 2. 准备并安装 Connector

### 探探 Gateway 的连接地址

Connector 入口：wss://11.158.199.29:49186/gateway/v1/peer

管理员交付的配置和文末模板都使用这个地址。拿到完整配置后直接使用，不需要自己寻找或填写服务器地址。

这是设备连接用的 WSS 入口，需要能访问该内网地址。浏览器 Web IDE 使用 /ide 返回的项目链接，不能把这个连接地址当作网页打开。

### 准备自己的设备

- 已安装且能正常使用 Codex，完成自己的登录或模型配置。
- 已安装 Git、Node.js 和 npm，Node.js 满足项目 package.json 中的运行要求。
- 设备能够访问上面的探探内网入口；不在相应网络时，需要已获准的内网或 VPN 连接。
- 首次启动使用交互式终端，方便核对并确认配对申请。

### 管理员开通个人准入，设备自行配对

先由探探管理员开通你的钉钉个人准入。管理员在 Gateway 开启设备自助登记后，你只需保存本文预填地址的 peer-client.json；设备显示名称可以自行修改。**不再领取设备 ID、device.token 或 CA 文件。**

首次启动，Connector 自动生成设备 ID 和随机凭据，保存在自己的 stateDir/device-identity.json 中。把终端显示的完整 /connect 命令发给探探，再回到本机确认申请人和开放范围，完成一次登记。登记前仅能配对，不能使用会话或 IDE；后续重连自动认证并恢复已保存的权限。

几个概念各有职责：

- **个人准入**：你的钉钉账号可以使用探探，由管理员设置，不需要填写准入码。
- **设备身份**：程序自动保存的独立凭据，用于重连时识别同一台设备，不在聊天中传递。
- **配对码**：终端临时显示、5 分钟有效的连接命令，用于把当前聊天中的本人和设备建立关系；仍需本机确认。
- **服务器证书**：确认连接的是探探。固定入口的公开 CA 已内置，省略 caFile，仍校验证书链、有效期及地址。

旧配置如果已有 nodeId 和 tokenFile，可以原样继续使用；二者须同时保留。不要直接删旧凭据或 stateDir，避免改变设备身份和丢失授权/回执。旧 caFile 若要改用内置信任，可在升级后移除该项。

如果只是使用别人分享的某个会话，请按第 8 节由提供者审批，不需要设备连接配置，也不必先申请机器人全部功能的准入。

### 下载和构建

如果管理员已提供构建好的 Connector 目录，直接使用该目录，跳到“放好配置”。从源码安装时，依次执行以下命令。

下载项目：

```sh
git clone https://github.com/yanjijinxiao/codex-im-gateway.git
```

进入项目目录：

```sh
cd codex-im-gateway
```

安装依赖：

```sh
npm ci
```

构建程序：

```sh
npm run build:bridge
```

安装完成后，后面的启动命令都在这个项目目录执行。无需启动另一套 Gateway，也无需配置机器人 AppKey 或 AppSecret。

### 放好配置

创建用于保存连接配置和状态的目录：

```sh
mkdir -p "$HOME/.config/tantan-connector"
```

将文末模板保存为这个目录内的 peer-client.json。探探地址已经填好，label 可改为自己的设备名称；其余按本机情况调整。新配置不含 nodeId、tokenFile 或 caFile。

Mac 上该目录位于 /Users/你的系统用户名/.config/tantan-connector；Linux 通常位于 /home/你的系统用户名/.config/tantan-connector。上面的终端命令会自动使用自己的主目录。

已有可用旧配置继续原样使用；程序不会擅自改变已配对设备的身份。

### 检查 Codex

先确认终端能找到 Codex：

```sh
codex --version
```

再确认它支持 Connector 使用的原生服务入口：

```sh
codex app-server daemon --help
```

若命令不可用，先核对 Codex 安装和可执行路径。已有 Codex 桌面 App 时，应使用相同系统用户及正确的数据目录，并确认桌面与 Connector 连接同一个原生服务，避免两个执行器争用同一会话。

## 3. 启动设备连接，完成第一次配对

在 Connector 的项目目录执行：

```sh
npm run peer -- --config "$HOME/.config/tantan-connector/peer-client.json"
```

连接成功后，终端会显示设备名称和一条带配对码的完整命令。

1. 保持终端运行，把它显示的 **完整 /connect 命令** 发给探探。
2. 私聊可以直接发送；在群里需要从成员列表真正 @探探，再发送命令。
3. 回到设备终端，核对申请人、机器人、聊天和开放范围。
4. 确认是你的申请后，在设备终端输入下面的回答。

```text
yes
```

5. 探探确认配对成功后，会直接显示该设备的会话目录，选择要继续的会话即可。

配对码有效期为 5 分钟，一次使用后失效。过期或被拒绝时，使用终端新显示的命令；必要时重启 Connector 获取新码。配对码由连接成功后的服务交互产生，不需要另外执行 curl 获取。

**配对针对具体用户、机器人和聊天。** 换到另一个群或私聊，需要在那里完成配对；不会因为知道设备名称就获得访问权。首次配对要在设备终端确认，非交互式后台启动不会自动同意申请。

完成配对后，Connector 仍需持续运行。退出终端或按 Ctrl-C 会停止这个前台 Connector；需要开机自动运行时，可由管理员配置系统服务。

## 4. 选择设备、项目与会话

### 选择已有会话

查看自己在当前聊天有权使用的设备：

```text
/connect
```

点击设备的切换按钮，或发送 `/connect use C2`（把 C2 换成刚才列表中的实际编号），即可保存当前 Connector。这个选择只对你在当前聊天生效，重启 Gateway 后仍保留，也不会更改群里已绑定的会话。

随后查看选中 Connector 承载的会话目录：

```text
/sessions
```

目录按“置顶 → 项目及其会话 → 其他会话”组织，没有未归档会话的项目也会保留，默认每页 50 项。一个 Connector 可以列出本机及已登记远端的项目，这不表示你又连接了一个 Connector。同名项目按主机和原生项目身份区分，不会合并；拿不准时，用列表里的详情查看主机和目录后再选择。

直接点选择按钮即可；需要文字命令时，使用目录给出的完整命令和实际编号。正常选择不需要手工填写 host，列表已携带目标主机。

选好后，核对当前设备、会话和工作目录：

```text
/status
```

然后直接发送自然语言，例如：请检查这个项目的登录流程，先说明现状，再修改问题并验证。

多设备时，先从 /connect 选择来源，再选择该 Connector 承载的会话完成换绑；仅切换 Connector 后，普通消息仍发往原绑定会话。`/sessions all` 显式查看全部可访问来源；`/sessions --host 主机ID` 只临时指定目录来源，不改变默认选择，使用 Connector 根标识时仍包含它承载的主机。所选设备离线或权限失效时明确提示，不自动换机器。`/project` 同样跟随当前 Connector；新建会话不能借用其他设备的项目目录。

`/connect use local` 仅用于管理员已配置的逻辑 local Connector，并要求相应准入；它不会自动识别或配对你的电脑，也不会绕过 Connector 在探探服务器执行。普通用户直接从 /connect 选择自己的设备即可。

设备上的会话由 Codex 管理，Connector 不要求你为每个会话重写配置。

### 本机与远端项目从哪里来

Connector 读取自己所用 Codex 数据目录的远端主机登记，再向每个目标主机的原生服务查询项目和会话。仅在本机磁盘创建文件夹，或只有一个远端主机名称，都不会凭空生成原生项目。Connector 所在电脑需要能用已有 SSH 配置访问这些远端；探探服务器不用直接 SSH 登录你的电脑或远端主机。

新增远端主机登记后，重启 Connector 更新它导出的主机清单，再查看 /sessions。已有主机上新增的会话只需刷新目录。部分远端不可达时，目录会提示缺失范围，其他可用主机仍可显示；不能把不完整目录当成项目已删除。

### 在项目中新建会话

查看设备上的项目：

```text
/project
```

从返回的真实项目中选择，并使用对应的新建入口。文字命令的 **模板如下，执行前把项目编号替换成列表中的实际编号**：

```text
/new <项目编号>
```

已经选定项目时，可以直接新建：

```text
/new
```

创建会话只建立工作上下文，下一条普通消息才开始执行任务。

需要无项目的独立会话时，先确认目标设备，再发送：

```text
/new --standalone
```

无项目会话不自动获得项目 Web IDE。项目列表为空时，应先在设备端核对项目登记，不能仅凭磁盘上存在某个文件夹就认为它已是可选项目。

## 5. 发送需求、附件与后续任务

### 普通消息与附件

绑定会话后，直接发送文字、图片或文件，并说明希望 Codex 如何处理。附件会转存到当前绑定会话的实际主机；即使 Connector 在 Mac、任务在远端 Linux，也不需要你手工上传第二遍。Codex 返回的文件通过探探发送到原聊天。只发文字时不会执行附件转存。

如果收到“附件未能转存到执行主机，这条消息尚未提交给 Codex”，说明这条输入没有进入 Codex，不代表原任务失败。先查看 /inbox 的保存记录；修复连接或升级后，按当前记录提供的操作处理，旧失败消息不会自动重发。若提交结果尚未确认，则先核对回执，不能据此重复提交。

任务运行时发送普通补充消息，默认会追加到当前轮次。若这个会话配置了不同的消息策略，以实际回执为准。

### 把多条消息合并成一次需求

开始收集：

```text
/prompt start
```

接着连续发送文字和附件，全部准备好后提交：

```text
/prompt done
```

放弃尚未提交的内容：

```text
/prompt cancel
```

/prompt 用于合并消息，不是查看系统提示词。取消收集不会停止已经提交的任务；多人群聊应避免交叉使用同一个收集区。

### 让下一件事排在后面执行

使用下面的 **命令模板，把占位文字替换为完整任务要求**：

```text
/queue <下一轮要执行的完整要求>
```

队列由设备上的 Codex 原生服务管理，需要该服务支持相应能力。查看当前聊天的队列回执：

```text
/queue list
```

探探暂时没有回复、显示断线或回执待确认时，可查看消息交接情况：

```text
/inbox
```

已经接收的输入、结果不明的提交，不会因为重连就自动重复提交。先看实际回执，不要连续重发同一个任务。

## 6. 进度、审批与任务控制

任务执行时，探探会更新 AI 卡中的状态、进展和工具信息。需要审批或补充回答时，使用实际卡片上的按钮；如果卡片提供文字回复方式，发送其中的完整命令。

阶段说明按时间保留在卡片里；公开思考摘要和工具活动只刷新最近一小段。下一阶段开始后，上一阶段的工具活动收成简短小结，不刷成长日志。接近卡片长度预算时，旧卡保留阶段记录并结束加载，后续进展放到新卡；这不会重启任务。进行中的复制框、状态样式和项目 Web IDE 入口保持不变，旧阶段卡不再提供停止命令。

卡片保留圆点、工具图标、思考图标与多行缩进。任务已由 Codex 确认结束、但结果还在核对或投递时，会显示“任务已结束，结果待同步”，并移除停止命令；项目 Web IDE 入口仍保留。这表示结果同步尚未结束，不需要重新提交同一任务。

**点击复制只复制内容，不会提交答案或批准操作。** 审批成功后，后续进展会继续展示。设备上 Codex 的沙箱和审批规则仍然有效。

| 看到的状态 | 如何处理 |
| --- | --- |
| 进行中 | 可以等待，或继续补充要求 |
| 等待审批 / 等你回答 | 处理对应卡片里的请求 |
| 执行状态待确认 | 用 /status 和 /inbox 核对连接及回执，不把它当作任务失败或仍在执行的证明 |
| 已完成 / 执行失败 / 已中断 | 阅读最终结果或失败原因，按需要发起下一步 |
| 会话已恢复（原任务未重试） | 只表示会话恢复可用，原先失败的任务没有重新执行，也不能当作已完成 |

确实要中断当前任务时发送：

```text
/stop
```

停止任务及审批等控制操作需要相应聊天角色。/stop 作用于当前绑定任务，不用于清理旧卡片或恢复网络。

只想解除当前聊天的会话绑定时发送：

```text
/unbind
```

/leave 也可用于解绑。解绑不会删除会话、停止原任务、取消原生队列或撤销设备配对；之后需重新选择会话才能继续发任务。

其他常用查询：

| 命令 | 用途 |
| --- | --- |
| /help | 查看帮助与可用功能 |
| /help session | 查看会话操作帮助 |
| /sessions more | 查看下一页会话 |
| /history 10 | 查看最近对话 |
| /history more | 查看更早的对话 |
| /role | 查看自己在当前聊天的角色 |
| /access | 查看本人在当前聊天的准入情况 |

## 7. 用 Web IDE 查看、编辑项目

完整 Web IDE 提供文件编辑、Git 和终端，适用于已开通的本机、远程或 Connector 项目。只有 CLI 的服务器也可以使用，不需要安装桌面图形界面。

### 开通一次，以后从项目链接进入

管理员需要在探探侧启用你的设备 IDE，并配置可访问的 HTTPS 入口；设备端也要开启 webIDE。配对聊天本身不会自动完成这一步。

要让 Connector 自动准备 code-server，在原 peer-client.json 中设置：

| 配置项 | 设置值 |
| --- | --- |
| webIDE.enabled | true |
| webIDE.binary | code-server |
| webIDE.autoInstall | true |

保留其他配置，保存后重新启动 Connector。首次打开 IDE 时，设备会检查环境，缺少 code-server 时下载、校验并安装，**无需用户另外手动安装 code-server**。这要求设备能够获取安装包且系统受支持；自动安装覆盖 macOS Intel / Apple Silicon 和 Linux x64 / ARM64，Linux 还需满足运行库要求。不支持的环境会明确报错。

设备已装好 code-server 时，也可把 binary 填为本机真实的绝对路径，并关闭 autoInstall。同一个 Connector 承载远端项目时，远端会复用自己已有的安装，不能照搬 Mac 的绝对路径；没有可用安装且未开启 autoInstall 时会提示缺少程序。

### 打开 IDE

在钉钉绑定一个项目会话后，发送：

```text
/ide
```

打开返回的项目链接即可。已有入口也会显示在对应的进行中卡片和最终回复中，同一个项目使用同一个固定链接。无项目会话不自动产生 IDE 入口。

浏览器中的文件、Git 和终端运行在项目所在设备上。设备离线时，这些功能也无法继续使用。

### 设置、扩展与 GitLens

进入 IDE 后，使用左侧扩展面板搜索扩展，例如 GitLens（发布者 eamodio），选择安装；卸载也在同一面板操作。主题、字号和扩展选项从编辑器设置调整。GitLens 的行作者和提交浮窗需要项目是 Git 仓库，且目标文件已有提交历史；安装扩展并不会自动创建 Git 提交。

扩展按当前 Web IDE 项目保存：桌面 VS Code 或另一个项目装过，不代表这里已经安装。安装后刷新已打开的 IDE，选中一行查看作者，再悬停查看提交说明和代码差异。没有出现时，先检查当前项目扩展面板的 GitLens 启用状态，以及设置中的 Current Line 和 Hovers。支持某个扩展、该项目已安装、实际显示功能，是三个需要分别核对的结果。

扩展下载超时时，可从该扩展发布者的官网取得 VSIX，再在扩展面板菜单选择「从 VSIX 安装」。只使用可信发布者的文件；安装后核对功能是否生效。

希望复用 VS Code 配置时，可请管理员在 Gateway 的 Web IDE 页导入：

| 文件 | 导入范围 |
| --- | --- |
| settings.json / JSONC | 编辑器与扩展设置，支持注释、尾逗号及语言覆盖 |
| .vscode/extensions.json | recommendations 中的扩展，排除 unwantedRecommendations |
| 导出的 .code-profile | 设置和启用的扩展；快捷键、代码片段、任务等其他部分不导入，会显示提示 |

导入只填写表单，保存后才应用。这是所有已启用主机的共同初始基线，修改可能停止受影响的 IDE 并要求重新建立访问资格，请先保存文件。不要在配置里放密码、令牌或个人登录资料。

初始安装完成后，重新打开不会把你卸载的扩展装回来。需要重新应用初始清单时，管理员先停止对应 IDE，再点击「准备扩展」。项目里的扩展推荐文件不会被 Gateway 自动执行成安装操作。安装失败时仍可进入编辑器查看错误、重试，但不代表扩展功能已经可用。

### 第一次打开为什么可能需要确认

访问方式由管理员为项目配置：

- **个人浏览器确认**：首次按页面完成本人确认，之后在有效期内直接进入；不需要再设置一套 IDE 密码。
- **持链接直接进入**：已开通的项目无需填写确认码，点击后直接进入并信任目录。链接具有项目开发访问能力，应只发给允许访问的人。

浏览器授权最长 90 天，到期或撤销后需要重新建立访问资格。

目前“持链接直接进入”按机器人账号配置授权来源。新用户配对成功，并不自动保证其设备也能直达 IDE；管理员仍需核对该来源是否有目标设备权限，再为该用户开通。遇到确认页或拒绝访问时，交由管理员核对，不能用其他人的设备授权代替。

仅获得文本共享权限的人可能看到“共享 Web 编辑器”，它不提供完整 Git 和终端。

## 8. 共享会话与多人群聊

### 谁提供会话，谁审批它的访问申请

会话提供者在自己的 Connector 设备上确认所有权后，由该所有者批准、拒绝和撤销访问。机器人管理员或聊天 controller 角色，不会自动取得他人的会话所有权或共享审批权。

这里有三种不同的准入，不要混在一起：

| 准入范围 | 由谁确认 |
| --- | --- |
| 机器人一般功能的使用准入 | Gateway 准入管理员 |
| 访问某台 Connector 设备的普通会话 | 设备端在配对时确认具体用户、聊天和范围 |
| 访问已经登记所有者的某个共享会话 | 该会话的所有者 |

**首次绑定会话不会自动登记所有者。** 默认设备配对允许访问该设备开放的普通会话；希望按会话单独审批时，提供者应先选中自己的会话，发送：

```text
/share claim
```

然后回到 Connector 终端核对身份和会话，确认所有权。登记后，其他已配对设备的用户也不能仅凭普通设备授权直接使用这个私人会话。

接着创建邀请：

```text
/share invite
```

把返回的完整 /join 命令发给访问者。访问者在希望使用的私聊或群聊发送它，提交申请；**邀请码只用于申请，不会直接授予访问权。** 共享访客可以申请指定会话，无需先获得机器人全部功能的准入。

所有者在仍选中该会话的聊天中查看申请：

```text
/share requests
```

核对申请人和聊天后批准。下面是 **命令模板，先把申请 ID 替换为真实申请 ID**：

```text
/share approve <申请ID>
```

批准后，访问者重新发送原来的完整 /join 命令即可绑定。授权限定当前用户、聊天和指定会话，不会开放整台设备，也不能转授权给别人。默认有效期为 24 小时；所有者可在批准命令中设置 --hours，范围为 1–168 小时。

所有者可用 /share list 查看有效授权，用 /share deny 拒绝申请，或用 /share revoke 撤销已授予的访问；按回复中的实际申请 ID、授权 ID 操作。

会话准入与工具执行审批也不同：能否续聊、停止任务、批准工具操作，仍受访问者在该聊天的角色限制。获得会话访问权不会自动获得完整 IDE 或终端；共享文本目录和文件回传需要所有者另行明确授权。

### 群聊共用当前绑定

**一个群只有一份当前会话绑定，群成员不是各自拥有一份绑定。**

例如：甲把群绑定到自己的会话 A；乙也获准使用探探，并在这个群配对了自己的设备。乙可以把群切换到自己的会话 B，也可以先解绑再绑定。之后群里的普通任务会发往 B，A 的任务不会因此停止。

按当前权限规则，已准入的普通参与者可以执行常规解绑和切换，不必取得首次绑定者的额外同意。个人设备访问仍需分别授权：乙能切换到自己的设备，不代表乙就有权操作甲的设备。

- 各自独立做事：分别私聊探探，或各用一个专用群。
- 共同处理一个任务：使用协作群，事先约定由谁切换会话、审批和停止任务。
- 不确定任务发往哪里：先查看 /status。

群里已经发出的结果和文件对群成员可见。当前没有“首次绑定者独占”规则。

## 9. 常见问题与恢复

| 现象 | 处理方法 |
| --- | --- |
| 探探提示尚未获准 | 联系管理员开通本人准入；确认原消息未提交后再发送需求 |
| /connect 没有设备 | 首次先启动 Connector 并配对；也要确认是否换了聊天 |
| 连接失败或不断重连 | 核对网络/VPN、入口和 Gateway 是否启用自助登记；旧配置另核对原设备凭据。不要删除 stateDir 重试 |
| 证书错误 | 核对设备时间、探探固定地址和 Connector 更新情况；旧配置显式指定 caFile 时，升级后移除该项。其他 Gateway 的 CA 由其管理员提供，不关闭证书校验 |
| 配对码过期或被拒绝 | 使用终端新显示的完整命令，并及时回设备确认 |
| 后台启动却不能确认申请 | 首次改用交互式终端，核对身份后输入 yes |
| 看不到自己的项目或会话 | 核对当前 Connector、目标主机、系统用户、Codex 数据目录和归档情况；远端离线时留意目录不完整提示 |
| 一个 Connector 下出现多台主机 | 同一连接可以承载本机与已登记远端，这是项目所在主机，不是重复安装了 Connector |
| 会话提示被其他应用占用 | 核对桌面与 Connector 是否连接同一个原生服务，不要删除锁文件强抢 |
| 消息显示已保存、尚未提交 | 查看 /inbox 和 /status，恢复连接后核对，不要重复发送 |
| 附件未能转存、这条消息尚未提交 | 核对目标主机和 Connector，查看 /inbox 的保存记录；这不等于原任务失败，旧记录不会因升级自动重发 |
| 任务已结束，旧卡片还显示停止入口 | 这是展示异常；不要用旧卡片的 /stop 清理，反馈给管理员核对 |
| /ide 没有入口 | 检查是否绑定项目会话，以及设备与探探两侧是否开通 IDE |
| IDE 安装失败 | 查看页面提示，由管理员检查下载网络、系统支持和安装状态后重试 |
| IDE 链接不可用 | 检查网络、授权期限、项目归属和设备权限 |
| 同群消息去了别人的会话 | 查看 /status，可能有成员切换了群的共享绑定 |

### 断线或重启后

设备保持开机和联网，Connector 会尝试重连。单独重启 Gateway 时，已由独立 Codex 服务接收的任务继续由该服务执行，Gateway 恢复后重新同步状态，不重新提交原输入。

本教程使用 daemon 连接，原生执行服务独立于 Connector。电脑关机或原生服务本身退出则是另一种情况，不能承诺任务继续。Connector 重启也可能断开浏览器 IDE 和其中的终端，操作前保存编辑内容。

### 更新 Connector

需要更新程序时，先在另一目录准备好源码、依赖和构建结果，再停止旧 Connector 并用原配置启动新程序，缩短断连时间。若源码目录存在自己的修改，先保存并处理合并，不能直接覆盖。按管理员提供的当前发布或仓库更新，不要求切回教程中某个固定 Git 提交。

**保留 peer-client.json、设备凭据、stateDir 和 Codex 数据目录；其他 Gateway 显式配置的 CA 文件也应保留。** 不要通过删除配对或执行回执来“清除卡住状态”；更新程序也不要求重新创建原有会话。

## 10. 管理员交付时需要准备什么

给新使用者交付时，完成以下事项即可让对方按本文接入：

1. 按 SQL 引擎部门的正式通讯录维护个人准入名单，使用返回的员工 userId 原值并保留前导零，不用群授权代替个人授权；已在名单内的使用者不重复审批。说明所需网络；仅申请共享会话的访客按所有者审批流程办理。
2. 在 Peer 监听配置启用 enrollment，保留已有 devices；新设备通过已准入用户的 /connect 和设备确认登记，不再逐台分发 token。交付预填实际地址的 peer-client.json 即可。设备摘要保存在 Peer 配置旁的 .devices.json，须随服务状态备份。
3. 指导用户在自己的交互式终端确认配对，并在钉钉选择自己的会话。
4. 完成一次实际往返，核对执行设备、工作目录、进展和最终结果。
5. 需要 IDE 时，为该设备开通完整 IDE，核对项目及访问权限，并实际打开链接确认文件、Git 和终端可用。
6. 说明群聊共享绑定规则，以及如何查询状态、解绑和联系管理员。

Gateway 本机 Web 管理页是管理员控制台，不是供所有探探用户登录的门户。用户日常通过钉钉和获准的项目 IDE 操作即可。

## 附录：手工填写 peer-client.json

这一节只供需要手工创建或修改配置的人使用。**已经拿到管理员完整配置的用户，不需要重新填写。**

### 哪些要填，值从哪里来

| 项目 | 谁提供、你是否要修改 | 填写方法或示例 |
| --- | --- | --- |
| url | 本文已填好，接入探探时保留 | wss://11.158.199.29:49186/gateway/v1/peer |
| nodeId | 新设备省略，由程序生成 | 已有旧配置保留原值，与 tokenFile 配套 |
| label | 你自己填写的显示名称；管理员已填好时可不改 | 例如“我的 MacBook”。可以使用中文，不影响设备认证 |
| tokenFile | 新设备省略，程序自动保存凭据 | 已有旧配置保留原文件路径，不填写令牌正文 |
| caFile | 连接本文探探入口时省略，不需要填写 | 仅其他私有证书入口或管理员明确覆盖信任时提供文件路径；显式配置始终优先，旧证书文件不会自动被忽略 |

label 为 1–80 个字符。新设备身份由程序随机生成；不要手工复制别人的设备状态目录。旧 nodeId 仍支持 1–80 个英文字母、数字、下划线或连字符。

### 通常保持默认的配置

| 项目 | 本教程使用值 | 含义 |
| --- | --- | --- |
| profileId | default | 连接资源标识，设置后保持稳定，不是 Codex CLI 的配置 profile 名 |
| backend | app-server | 使用统一原生 Codex 接口，保留即可 |
| appServerTransport | daemon | 连接独立原生服务，保留即可 |
| stateDir | ./state | Connector 保存设备身份、配对授权和执行回执的目录；自动维护，更新程序时保留 |
| webIDE.enabled | false | 初次只接通聊天；需要完整 IDE 时按第 7 节开启 |
| webIDE.binary | code-server | IDE 程序名称；使用自动安装时保留此值 |
| webIDE.autoInstall | false | 初次不开启 IDE 安装；按第 7 节开通时改为 true |

false 和 true 是 JSON 布尔值，不加引号。不要把某个 session 的 ID 填进 profileId 或 stateDir。

### 仅在本机环境不同时调整

| 项目 | 何时需要修改 | 怎么填 |
| --- | --- | --- |
| codexBin | 终端里不能直接运行 codex，或需要指定另一处已安装的 Codex | 默认 codex；必要时填本机真实可执行文件的绝对路径，例如 /opt/homebrew/bin/codex。示例路径不保证存在，先核对本机安装 |
| codexHome | 你的 Codex 使用了非默认数据目录 | 默认不写这一项；需要时增加本机实际路径，并与桌面或 CLI 使用的目录保持一致 |

文件及数据目录的相对路径按 peer-client.json 所在目录解析。例如 stateDir 为 ./state 时，状态放在配置目录内的 state 子目录，与启动命令所在的源码目录无关。codexBin 是可执行命令，默认通过 PATH 查找；需要固定位置时使用绝对路径。

JSON 中的 `~` 和 `$HOME` 不会像终端命令那样展开。需要引用主目录时，填写真实绝对路径，或使用相对于配置文件的路径。

### 完整配置模板

下面模板可保存为 peer-client.json；label 可自行修改。探探地址已预填，设备凭据自动生成，CA 已内置。

```json
{
  "url": "wss://11.158.199.29:49186/gateway/v1/peer",
  "label": "我的电脑",
  "profileId": "default",
  "backend": "app-server",
  "appServerTransport": "daemon",
  "codexBin": "codex",
  "stateDir": "./state",
  "webIDE": {
    "enabled": false,
    "binary": "code-server",
    "autoInstall": false
  }
}
```

保存时使用普通 UTF-8 文本，保留英文双引号，不添加注释或末尾多余逗号。不要把 Markdown 的代码框标记一起复制进文件。

### 启动前核对

1. 本人已有探探个人准入；label 是自己能识别的设备名称。
2. 探探地址保留为上面的完整 WSS 地址，路径也没有删掉。
3. 新配置省略 nodeId、tokenFile、caFile；旧配置保留原设备凭据。
4. Codex 能在这台设备正常运行；需要指定安装路径或数据目录时已按实际填写。
5. stateDir 保持稳定，没有第二个 Connector 同时使用它。

**不需要填写**钉钉用户 ID、群 ID、session ID、配对码、机器人 AppKey/AppSecret 或 Codex 登录密钥。连接成功后，Connector 才会显示带配对码的完整 /connect 命令；按第 3 节在钉钉发送，并在设备终端核对确认。

## 模型、推理强度和计划模式

绑定会话后，使用 `/model` 查看并选择模型，`/effort` 选择推理强度，`/plan on` 或 `/plan off` 切换计划模式。这些操作直接修改你设备上该 Codex 会话的原生设置，从下一轮生效；修改设置本身不会启动任务。

探探不另存一份覆盖值。在 Codex App 改过模型后，之后从探探发消息也沿用该会话的最新原生设置；Gateway 或 Connector 重启不会把旧值盖回来。旧的 `/model default`、`/effort default` 命令现在只查看当前原生值。`/stream` 控制的是探探的进度展示，仍作为展示偏好保存。

如果设备上的 Codex 或 Connector 太旧、不支持原生设置接口，会明确提示升级，不会显示假成功或把设置偷偷存到 Gateway。设置回执未确认时先查看当前设置，不重复发送任务。
