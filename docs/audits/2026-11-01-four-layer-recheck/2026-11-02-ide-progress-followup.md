# IDE 前置读取超时及重连期间进展链接

逐张查看本轮两张本机附件：0秒卡片含IDE页脚，3分钟的同任务进展卡缺少页脚；IDE trust回复为project/list preflight通信错误。线上日志对应远程project/list读取超时、重连后再次超时；只读管理接口确认远端入口reconnecting、本地ready、授权文件未报读取错误。诊断只说明前置读取未完成，不把静默原生任务判为失败，也没有自动重发trust或批准浏览器。

根因：EndpointManager.accessOrigin只在入口ready时返回URL；进展卡每次重投影因此在远端中继重连时删除了已有固定地址。修复将仅供展示的地址与live入口就绪检查分开：只允许原远程中继的reconnecting状态沿用当前精确端点，普通访问/授权仍拒绝未就绪入口。关闭/停用/本机网卡歧义或离线不保留旧IP。项目/host/root身份和已有浏览器授权不放宽。

IDE确认命令捕获明确preflight通信错误，显示“前置核验超时，未批准浏览器”。真实服务的approveAccess先refreshWorkspace及canonicalForTrust，之后才保存授权；没有用缓存目录绕过信任核对。申请原有过期/单次消费规则不改，失败后必须从原浏览器获取仍有效的当前确认，不自动批准。

原版隔离源码两个反例失败；修后IDE入口/真实流展示/审批/热插拔及会话目录85项定向通过。完整根回归首次2549项中2544通过、4处旧表格断言失败、1Windows跳过；保留失败日志，迁移断言为真实项目树，同时保留103会话稳定R、过滤、偏好、Feishu精确按钮与文本不丢行验证。最终发布会独立重跑全量，不把定向或本机检查冒充手机验收。

四层核对：架构分离地址/健康/授权，模块沿进展投影与前置批准顺序，文件逐行审查受影响差异并继承字节相同部分，静态合同及case同时记录。未改远程网络配置、未重启Codex、未向真实群发送测试消息。远端网络不可达仍需独立恢复，不能把显示修复报告成远端已上线。

上线前发现发布脚本还要求全部远端入口ready，既有远端网络故障因此会阻止Gateway重启。改为精确比较切换前后：原ready不能退化，原远端reconnecting可维持重连；本机失败、新error、host/origin变化仍拒绝。消息交接lease、ACL、浏览器grant和绑定核对不改变。此发布规则是静态工具职责，不进入产品输入或任务生命周期。
