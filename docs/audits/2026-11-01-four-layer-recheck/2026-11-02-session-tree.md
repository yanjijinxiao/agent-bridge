# /sessions 项目树与验证缺口

用户要求中间段仿照 Codex 以项目+session 组织，空项目也保留。原版 e32322f 的 Bridge 用同一份空/归档/仅置顶/普通项目夹具，无法显示空项目；隔离复制的原版源码失败记录保留本机。修后同例通过，项目数据不写入管理状态。

架构：原生项目/会话是事实来源，展示项和 R 身份分开；不增加执行器或项目归属推断。模块：目录生成包括空项目，排序先固定真实会话身份，再分页会话/空项目；离线及部分目录不伪装为空，搜索不混入无关目录。文件/函数：复核 handleSessionCatalog、sessionCatalogItems、共享 ChannelClient 选择及钉钉真实渲染路径。静态/配置：中英文命令帮助、模块合同、需求及缺测清单同步；默认10、5至50设置、15分钟快照不变，无配置迁移。

沿真实发送路径检查后，发现非表格卡会经公共层的小容量文本回退，虽然仍可创建 AI 卡，却会过早拆卡；不能把适配器的未调用分支当作实际路径。分离静态卡展示与按钮能力后，8个长项目一张卡，50个长项目有界分片且保留完整行/必要回复。旧公共层及旧适配器配新项目树时，8项目同例失败。没有修改审批 mentions 路径、执行权限、原生连接或真实 IM 绑定。

当前246项目录/钉钉定向回归通过，新增9个精确场景。首次在受限进程中运行时，SDK WebSocket隔离端口监听被 EPERM 拒绝；保留原日志并在获准本地端口环境重跑通过。该失败不是产品修复或真实手机验收证据。发布前完整类型检查/根回归由隔离 release prepare 记录。

缺测报告逐项保留28个未直接映射case及97个partial；本次新增CAT-02.4窄边界不消除其他缺口。手机实机指真实手机钉钉显示/操作以及手机到IDE的连接，并非新的读写权限或发布门禁；本轮没有向真实群主动发测试消息，没有完成设备验收。

额外共享渠道回归发现：两处断言仍要求旧表格/旧帮助文案，已按新展示更新并保留原身份、只读和省略细节断言；另发现非表格完整回复不能仅由body重建，已保留其完整文档。追加实际钉钉多页第二页回执丢失的场景，确保只保留已确认页且不改发/重发。各阶段失败日志保留本机，不把失败测试改名后当作从未失败。
