# 飞书与企微出站媒体适配

## 架构层

用户继续剩余开发。本轮完整路径为：显式结果send动作→Bridge原来源/主机核对→ChannelClient能力选择→渠道媒体端口→原生上传资源→原生消息发送→TurnResultActions确认或保留未知。没有新增执行器、提示词重放、上传后自动文字降级，也没有修改任务/审批生命周期。

## 模块层

适配器组合FeishuMediaSender/WeComMediaSender；共用readOutboundMedia的单描述符有界读取。能力由实际SDK端口声明，SDK方法缺失保持不可用。飞书文件stream、MP4视频mp4/media；企微SDK三步分片保留原type/filename。真实SDK分别对本机HTTP/WebSocket检查，不访问真实供应商账号。

发现并处理SDK状态丢失边界：当前Lark file/image.create返回res.data，原始非零code可能被剥掉。每账号SDK工厂先检查raw业务码，再让SDK解码；不能用上传key代替消息回执。测试向API返回非零/缺失code并同时放有效key，仍必须0消息发送。

企微群/单聊只依据平台chattype，actor保持from.userid。已知single回复from.userid，不被多余chatid改成群目标；已知group必须有非空chatid，否则在持久认领前拒绝。未知种类保留原目标兼容规则，但不从chatid猜群。仅真实group与合法用户ID生成结构化成员身份，不把all/标签/显示名变成@授权。原生@能力仍未实现。

## 文件与函数层

逐项复核新媒体发送器、原始/解码响应、收件人类型、共享文件读取和监控入口diff；没有把旧完整阅读区间当成本轮重读，字节未变区间才继承原记录。selected function contracts登记对应职责和case。

有界读取处理空/目录/超限，实际文件在stat后增长或缩短必须失败且关闭句柄；上传只使用已读取的原字节。上传成功与平台消息成功分开；缺回执/业务拒绝/发送断连均不记done；跨日志重建不重传确认或未知的媒体。临时副本清理由既有远程回传租约负责。

## 静态与配置层

无新凭据字段/配置迁移，无网页布局变更；核对能力矩阵、权限说明、文件限制、模块与需求case。飞书须具备资源上传和机器人发送消息权限并发布；企微复用原长连接账号。不操作真实权限、不发送真实IM，不将文档更新称作手机验收。

## 验证边界

定向检查包含飞书三类媒体的真实SDK原始响应、三种收件人类型、原文件名与multipart字节，企微真实SDK两分片/MD5/关联req_id及一次媒体消息，真实Bridge与持久动作日志确认/未知跨重启、读取期间文件变化。企微图片/视频的SDK接口调用和错误组合另用受控端口验证；没有宣称真实平台全类型验收。

开发夹具修正单列：能力拒绝可能同步抛出，assert.rejects需包异步调用；SDK的custom domain端口会被path-template当变量，协议夹具改为只在HTTP传输边界重定向到本机；相同路径动作会被现有解析层去重，三类媒体的Bridge用例应使用各自文件，而不是改产品去重。保留原业务断言。最终结果以测试日志精确名称与SHA为准。
