# 78 个待验场景需要什么条件

本表保存复验前的环境判断。[复验结果与剩余条件](2026-11-25-pending-acceptance-results.md)逐项给出后续通过记录。

2026-11-25，逐项核对了功能清单里状态为部分覆盖的场景、已有断言及各自的待验条件。下表按补齐每项最后一段证据所需的条件计数，每个场景只出现一次。本次评估可执行性，未更改验收状态或线上配置。

| 主要条件 | 场景数 | 当前可做的事 |
| --- | ---: | --- |
| 本机隔离环境 | 33 | 用独立账号数据、进程、原生核心及 Chrome，补并发、迁移、异常回执和界面回归。 |
| 已有 Mac 与 Linux 12 | 5 | 用测试专属的 SSH 连接、远程目录、原生线程及 IDE 做跨机验证。 |
| 真实服务账号、测试渠道或平台回执 | 14 | 程序内的时序可先模拟。完成整项需真实审批、投递、重投、部分成功或第三方服务等对应证据。 |
| 收件客户端或真实成员 | 19 | 对照真实显示、提醒、复制、表单、手机布局等。其中只有注明手机的场景要求手机。 |
| 特定设备、故障现场或发布窗口 | 5 | 分别是知游的目录、Linux ARM64、跨平台回滚、真实发布、线上远程 IDE 恢复。 |
| 原图或其他场景的汇总 | 2 | 一项等原图，一项随其他部分场景补齐而更新。 |

**现在可先开展 38 项。** 本次在 Mac 核对了 Chrome 和原生 Codex，SSH 登录 Linux 12 确认为 Linux x86_64，复核其 Codex 与 code-server 可执行文件。两端前次已有命名实测记录。具备环境的场景仍需补组合、控制故障时序及采集断言。其他 40 项中，有些自身的程序逻辑也能先测。只有待验条件全部满足才更新状态。

**群成员独立会话。** 7 项中的 6 项已有证据，最后一项是 DEL-11.2。目标 Gateway 需运行包含此功能的构建，钉钉账号开启「群内每人独立」及进度卡。若同时验首条消息自动创建，再开启该策略并选可用默认 Connector。在同一测试群，两位已准入的真实成员分别发不同内容，两轮有足够时间出现进行中卡，再各自核对最终卡的会话和机器标题，以及谁收到 @ 提醒。消息本身在同一群都能看到。这个场景用桌面钉钉即可，只有手机排版另有要求。

Linux ARM64 可安排独立机器，或在 Apple Silicon 上准备原生运行的 ARM64 Linux 虚拟环境验证实际 ABI、安装、激活和工作台。Mac 上装有 Docker Desktop，本次检查时其本机服务套接字不存在，尚未取得该环境的运行证明。Windows node.exe 同目录 npm 的专用用例是上轮全量的跳过项，另记运行结果，不额外算作第 79 个部分场景。
