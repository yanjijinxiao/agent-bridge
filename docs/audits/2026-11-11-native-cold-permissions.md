# 原生冷恢复权限（NATIVE-02.8）

## 缺陷与边界

会话 01a15d9b-5264-78e0-ac21-8ba577ada051 中的隔离复现及远端保存结果证明：Codex 0.167.0 后端进程重启后，不带覆盖的 thread/resume 会保留 workspace-write/on-request，却把原先的 networkAccess=true 和额外 .git 写目录还原为配置默认值。该问题不同于仅替换 Gateway/Connector、原生线程仍加载的暖重连。

旧 NATIVE-02.2 矩阵保持同一 server PID，只核对 sandbox 类型、审批策略和 reviewer；不证明冷恢复网络和额外目录完整。本次不更改建群 skill，不调整全局 Codex 配置，不重启用户原生核心，不修改已经丢失权限的历史记录或倒退到更早的宽授权。

## 架构和函数设计

- 原生 rollout 是恢复事实源，没有 Gateway/Connector 权限缓存。只对 thread/read 证实 notLoaded 的会话读取；所有已加载状态只附着，不回放权限。显式拥有设置的 UI 请求保持原覆盖语义。
- 通过同一 App Server 的 fs/readFile 读取其 thread/read 返回路径，本机、SSH 远端和纯 CLI 共用逻辑。禁止读取同名本机文件、shell/SSH 业务回退及持久化副本。该原生接口目前不支持分段，解码限制 128 MiB，内容只在 Connector 内解析，不写日志或回传 Gateway。
- nativePermissionResume 校验首行精确线程身份，按原生顺序选择最新完整 settings-applied/turn-context，包含显式收紧、空目录和断网。新记录有问题时不倒退到旧记录。现代 permission_profile 和旧 sandbox_policy 都验证；不把 deny、glob、限定读目录或未知权限表示压平成更宽的 workspace-write。
- resumeThread 是全部六个恢复入口的统一边界：续聊、systemError 恢复、空闲 queue 附着、队列已接收轮次附着、执行设置更新及交互订阅。权限读取完成后再次校验 actor/binding，再发单个 thread/resume；不追加 settings/update、占位 turn 或输入重发。
- 当前 resume API 支持具名 permissions、sandbox 模式和 config 覆盖，没有任意完整 sandboxPolicy。具名配置按原生 active_permission_profile.id 重新选择，保留域名、deny 及配置后改；可无损表达的传统 workspace/read-only/full-access 配置才转换。不能无损表达的匿名复杂配置明确失败，不能授予额外权限。读取失败/损坏/半写记录同样在输入提交前失败。
- 模型、effort、Plan、指令、项目归属保持原生权威，权限恢复投影不包含这些字段。并发已有所有者时原生 resume 仅附着，不用后续权限写入强行校正。

## 检查与验证计划

1. 架构：原生唯一权威、cold/warm 分离、统一恢复入口、无重复持久化、输入接收与恢复交接分开。
2. 模块：Codex App/CLI，同核客户端替换/核心进程替换，本机/远端传输，原生后改与显式 UI 设置，队列/审批/模型设置入口。
3. 函数和代码：逐行检查记录解析、身份与新旧记录选择、无损投影、所有恢复调用点、异步读取后来源守卫；测试损坏/未知/半写/跨线程及授权收紧。
4. 静态和配置：本文件、native-protocol 模块、NATIVE-02 功能契约、CHANGELOG；不增加权限配置、凭据、协议版本或永久缓存。

真实回归须重启临时 CODEX_HOME 的测试自有 App Server，并更换 Connector 客户端，核对 PID 改变、网络/额外根/临时目录排除、审批策略/reviewer、空输入及模型请求次数。常规协议替身与真实原生结果分别记载，不以条件跳过替代通过。
