# 2026-11-25 四层自检续查

本轮修复了代码批注丢失位置、Herdr 终端重连时改变绑定状态、审计脚本接受空缺口说明三个问题。另以独立运行的 Gateway 和本机 Codex App Server 验证了群解绑后的队列与崩溃恢复。下列数据对应本次工作树。

## 第一层 · 需求与架构

98 项要求下的 489 个场景逐项核对了实现引用和测试记录。上次有 393 项在列明范围内验证、96 项部分覆盖。这次补验的 11 项为 BIND-01.2～3、CAT-03.1、CTRL-05.2～3、CTRL-06.1～6。其余 85 项在需求清单中各自记录了待验条件。Herdr 专项单独记账。

确认了三处分工。Gateway 持有群与线程的绑定，原生执行器持有活动轮次及队列；解绑其中一个群时，其他群及原线程可以继续工作。模型和推理强度归原生线程，IM 和 Web 自己保存流式展示偏好。进度卡、最终答复、定向提醒、历史以及纯文本共用代码批注展示函数。具体契约和案例见[功能清单](../architecture/gateway-case-coverage.md)和[机器可读索引](../architecture/gateway-requirements.json)。

## 第二层 · 模块行为与异常

| 场景 | 实际验证及边界 |
| --- | --- |
| 同一条代码审查意见指向多个位置 | 原实现按说明文字去重，两条批注位于不同文件时，第二个文件从输出消失。新回归在旧实现上失败。现在按批注的结构化字段识别重复，保留各自的文件、行号及行范围。覆盖普通文本、进行中的摘要、最终卡、合并定向提醒卡和实际 Bridge 的 /history。相似标识符、完全重复、围栏与引用有单独对照。真实钉钉最终呈现仍在 DEL-09.4 中列为待验。 |
| 查询状态时 Taskboard 长时间无响应 | 单独挂起 Taskboard 查询，/status 在 2.5 秒的测试时限内仍能返回 Codex 模型与执行状态。五个单命令帮助入口分别检查用户实际看到的操作说明。 |
| 设置同步与提交回执 | 两个独立协议客户端操作同一隔离原生核心，验证忙碌时修改模型、下轮生效、连接替换、其他客户端读回，以及接收未知时不重复写。还检查了 Web 单字段更新、旧设备能力及 IM/Web 普通输入。 |
| 已解绑的群遇到 Gateway 骤停 | 两个群绑定同一原生线程。第一条消息执行中，第二条已进入原生队列；从第一群发送 /unbind 后强制终止隔离 Gateway。用原状态目录启动新进程，从第一群再发普通消息并检查未绑定提示、持久解绑标记和另一群的绑定。原队列条目的 ID 保留，两条输入按各自原生 ID 各完成一次，模型共收到两次请求。Gateway 和 App Server 是真实子进程，IM 与模型是本地夹具。 |
| 无当前项目 | 注册两个项目后分别发送普通消息和 /new，核对两次均无活动项目、无绑定、无新增会话。显式 /new --standalone 才创建一条独立会话。另核对 /task list、/qa、/mode session 三种命令均未暗选项目。 |
| Herdr 终端未报告目录 | 旧实现创建时将项目归属记为 none，加载历史时又改为 unknown。状态层复现失败。现以 unknown 贯穿创建、重载和重新绑定；Herdr App、TUI 两条入口均核对执行代次不变，又复现了只有项目 ID、缺少绝对目录时，写入的状态在下次加载时报 Invalid unknown workspace state。现在这条不完整观察保留原绑定，绝对目录真正出现时才更新。 |
| 群成员独立会话 | 两个成员可分别建立会话，过程卡和最终卡按所属成员收取回执，保留定向提醒。已重跑带真实 App Server 的隔离链路。生产群里两位真实成员各自确认所见卡片、标题和提醒仍待验收。[成员会话记录](2026-11-25-member-sessions.md) |
