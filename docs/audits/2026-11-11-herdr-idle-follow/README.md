## 四层范围

1. 架构：被动订阅与输入持有者分开；画面摘要只是显示证据，不替代原生执行/回执，不新增消息队列、原文历史、自动重发或执行入口。Codex 原生阶段卡与 Herdr 整段终端窗口继续独立。
2. 模块与异常：静默基线、重复空闲状态、变更画面的快速任务、实际 working/blocked/error/exited、重连/重建、stream 关闭、输入与读取竞争、读失败、授权撤销及目标替换分别检查。新读取前后的资源身份和绑定守卫不放宽。
3. 文件与函数：逐行复核 runtime-observation 的 rowSchema、follow、readScreen、observeNow、finish、resetFollow 及 journal 持久写入；terminal-presentation 的清理、Markdown 转义、窗口字节预算；相邻 BridgeService 的构造及 runtime 输入接线和 ChannelTurnPresentation 的 terminalScreen/最终卡路径。详细列出的版本、范围与测试边界见本目录结构化记录，不声称全仓重新逐行审查。
4. 静态与配置：复用既有 display v1 容器，以 terminal-window-v1:sha256 类型标签区分新摘要和旧阶段边界，摘要与状态/序列原子落盘。没有扩展状态 schema 或改变账号/权限/绑定配置。同步功能、模块、session 索引、教程和变更日志。终端显示不引入 HTML 实体，既有停止控件与 IDE 页脚继续使用可信区域。

## 验证及限制

旧实现运行初始 66 项定向检查，50 通过、16 失败，包括旧画面误推和钉钉标点反例，以及静默读取基线的新契约断言。修复过程中新增“读取期间变为 error/exited”两例也曾失败，补齐状态变化观察后通过。最终定向 70 项通过。发行准备在同一干净提交上完成 Gateway 3,798 项（3,707 通过、91 跳过）及 Taskboard 510 项（508 通过、2 跳过），均无失败；两套类型检查和完整编译通过。

默认沙箱拒绝部分本机 socket/端口（EPERM），相关联调在获准的临时环境重跑，不能将最初未启动的网络测试当成业务回归失败。无效读取不发布摘要；旧格式无基线时首次静默建立比较点。若某外部任务完全发生在两次观察之间且画面不变，无法据当前接口识别它，采用静默策略；Gateway 输入自己的结果仍按原交接持有，不受此限制。

本次只需更新 Gateway 的观察与渲染代码，Herdr App/TUI、Codex 原生进程及 Connector 不需要重启。修复构建版本为 0.6.3；npm 正式发行仍单独记录，不将内部上线写成 npm 已发布。现场标识与业务正文只留在本机排查记录，仓库不复制群 ID、用户信息或终端原文。
