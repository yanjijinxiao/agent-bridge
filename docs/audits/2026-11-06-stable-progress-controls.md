# 进行中卡片复制控件重复回归

## 事实与旧约束

用户 11 月 6 日截图中，同一卡片出现两个 `/stop` 复制框、三处“复制不会发送”。10 月 26 日的同类问题已记录在 task-card-status.md；10 月 29 日恢复复制框时也明确要求动态正文与静态操作页脚分开。

5607ef7 为限制流式帧大小，把阶段正文和页脚合并到 staticMsgContent。正文变化因此会重复写入包含代码块的组件。DEL-09.3/09.5 只检查最终合成字符串中控件唯一，未约束正文更新的字段写入集合，未能挡住这次架构回退。客户端内部重复组件的完整因果链仍不能由 HTTP 成功回执证明。

## 修复与四层核对

1. 架构：阶段事实、正文展示、操作区各有职责；状态/阶段/活动合用模板原正文区，控件独立。长任务完整正文以普通卡片更新，不塞进流式接口。Gateway 恢复 IDE 连接只管理 IDE，不影响 Codex 任务。
2. 模块：HTTPS/SDK 连续更新只发送差异键；创建回执初始化缓存，失败不推进，重连初始化原卡；等待与终态切换仍清理停止入口。IDE 上游失效后撤销旧 endpoint 的可复用状态，下一次经原授权和 CSRF 检查的 POST 重建；GET 不启动、写请求不重放。
3. 函数：核对 activeDingTalkLayout、两个客户端的 create/update、changedDingTalkCardFields；IDE endpoint/invalidateEndpoint/open、代理错误分支及按主机包装层。用实例 ID 和 socket 路径同时限定失效代次，避免旧错误破坏新连接。仅分析/工具开始事件不生成“未收到回执”的阶段占位。
4. 模板/静态/配置：真实公共模板忽略候选 progressContent；该方案已撤销。最终使用已绑定的原正文区和 staticMsgContent，不改账号模板、权限、原生任务或持久化结构。同步功能场景、模块文档及函数记录。

## 验证记录与边界

- 原实现 DEL-09.6 两项反例失败；修复后 HTTPS/SDK 20 段正文、控件仅真实变更、重连、失败重试、终态清理通过。
- 获用户允许，仅在当前群复用一张标记“回归测试”的卡。精确消息读回 2,566 UTF-8 字节，含长正文结束标记、第二次正文更新及唯一复制项；没有采用未绑定的第三字段。此证据不是手机像素验收。
- 原探探回归群已无机器人，投递被平台拒绝；没有擅自加机器人。测试现有模板使用当前群的头头。
- IDE 模拟上游失效但进程仍活着，确认导航进入原授权恢复表单、GET 不启动、POST 恢复、晚到旧错误不能撤销替换实例、失败写请求不重放。
- 最新全量与部署状态待完成后记录，不以单元测试通过声称线上已修复。

最终候选验证：typecheck 通过；全量 3,362 项，3,274 通过、88 跳过、0 失败。真实回归卡已以完成态收尾。远端 IDE 两个现存 socket 中，一个探测 EPIPE、另一个健康检查 HTTP 200（约 6.9 秒）；指定项目的管理打开请求超过 60 秒，尚不能据此确认浏览器可用。
