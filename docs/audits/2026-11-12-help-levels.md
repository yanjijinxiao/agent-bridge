# 帮助分层与命令入口增量检查

## 用户要求与实现范围

本 session 本轮要求：精简默认帮助，保留完整及分项参考，统一 Codex 与 Herdr 的帮助接口；兼容写法继续工作；IDE、跟随与共享等入口按常用/诊断/高级分类；功能和模块文档随开发更新。

本次检查覆盖命令定义、语法解析的直接依赖、帮助及按钮、两种后端入口和相关文档；不宣称全仓重新逐行审查，不更新原生协议、不切换执行器、不修改线上配置。

## 四层检查

1. **架构**：名称、22 个别名与帮助共用 `channel-command-registry`。`channel-commands` 保留原解析/分类公开接口；`runtime-command-policy` 只改导入来源。共享帮助只读消费元数据，不拥有权限、绑定或执行状态。
2. **模块及正交组合**：首页/完整/五分项/单命令；Codex 与 Herdr App/TUI；四 IM 渠道与文字/卡片；模式、Taskboard、知识库和原生能力独立；无绑定时读取所选来源的能力；扩展后安装与别名冲突；原审批、问题、待确认输入和队列记录保持原归属。
3. **函数及代码**：逐行复核 `selectCommandHelp`、`commandHelpRestriction`、`variant`、`visible`、`commandHelpChoices`、`commandHelpText`、两兼容格式器、`createMainMenuCard` 以及 Service 的帮助分支/上下文/终端路由。既有解析函数及其他 Service 方法按 AST 函数体对照未改变；新数据清单逐条对照原命令语法和职责。更新函数合同的文件 SHA 与行号不是重跑所有旧功能的声明。
4. **静态、配置和文档**：类型检查；36 个命令完整参考及 22 别名保留；首页无重复兼容入口、授权模板或危险操作按钮。功能合同、模块合同、session 索引、命令审计、兼容性说明、README 和探探教程同步；Markdown 相对链接与差异空白检查。版本、部署、Gateway/Connector 配置均不改。

## 反例与验证

原测试强制所有命令和高级操作出现在首页、旧固定卡片按钮与完整帮助重合。本次把“首页简洁”和“完整参考无遗漏”分别验证，旧完整清单测试改查 `/help all`，不删除功能或减弱执行权限测试。

专项测试覆盖 CTRL-05.help-1～help-8；其中 HELP-05 分别验证 Herdr App/TUI，HELP-08 分别验证四渠道 × 卡片/文字，不读取原生写入者、不提交、不改变会话/项目/模式。现有新建、解绑、原控制、扩展与 Herdr 协议替身继续回归。

初次完整回归：3,929 项，3,821 通过、101 跳过、7 失败。6 项失败来自旧首页/扩展帮助断言，已按新合同修正；另 1 项是未改动的 IDE 上传清理 500ms 时序超时，隔离复核通过，未修改该功能或测试阈值。最终结果以同目录 JSON 检查记录为准。

最终完整回归：3,930 项，3,829 通过、101 条件跳过、0 失败；包含新增未绑定目录来源场景。最终能力组合补核再跑 135 项，全部通过，包含观察能力不可用时仍可查看/关闭/恢复本地展示设置。类型检查通过。完整回归后这项展示细节按最终专项核验，不把日志对应范围混为同一源码快照。详细日志摘要、SHA、函数与文件范围见[机器记录](2026-11-12-help-levels.json)。

## 验收边界

本次是本地源码、字符串、卡片及隔离 Bridge/协议场景验证；没有向真实群发送测试卡，没有发布 npm，没有重启或升级头头、探探。相关部署需要单独执行和核验，不以本地测试通过代替线上版本。

帮助只按已知能力过滤；未知能力不冒称已支持，实际操作仍由原处理器判断。目录、共享、审批、恢复和 IDE 本身的现有边界保持原合同。
