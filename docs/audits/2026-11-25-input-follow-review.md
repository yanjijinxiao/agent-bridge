# 消息介入、权限变更与历史恢复的四层自检

2026-11-25，本次核对当前工作树中一条群消息从进入 Gateway、发往 Codex，到卡片展示和重启恢复的完整路径。这次续检开始时，151 个清单文件还缺阅读行段。结束时，1,125 个现存产品文件中，1,087 个文本文件在当前版本均有完整行段记录，另外 38 个制品有结构或视觉检查记录。还逐路径比对了 Git 已跟踪文件和工作树新增文件，清单外只有审计材料及本机 Finder 元数据。

98 项通用 Gateway 和 Codex 要求共 489 个场景，对应 1,927 条不同的命名测试和 398 份精选函数契约。7 个场景本次补齐证据，累计 411 个在所列边界内验证，另有 78 个仍有具体条件待验。Herdr 的专项合同另记。群成员会话与卡片标题的 7 个新场景中，6 个已在列明边界内验证，剩余 1 个需要生产群里的两位真实成员各自查看进行中卡、最终卡、标题和定向提醒。详见[当前清单](../architecture/remaining-work.md)。

## 第一层 · 架构与状态归属

显式 `/steer` 指定原生线程和活动轮次。成功提示必须有这两个目标的匹配回执。普通输入可以由原生执行器决定新轮次。群成员、账号和绑定的写入权限由 Gateway 判断，异步建立连接之后，仍须以即将发出写入时的权限为准。执行结果由原生执行器确认；旁路读到的旧历史只用于观察。

## 第二层 · 模块间的交接

| 路径 | 发现与处理 | 实际观察 |
| --- | --- | --- |
| `/steer` → 原生回执 → 卡片 | 原实现接受了其他轮次的回执。显式介入现核对线程与轮次，遇到不符保留提交未确认状态。原生协议仅返回正确轮次的标准回执仍可用。 | 覆盖原生命令、Bridge 错误提示和落盘恢复。重启后再次处理同一输入，原生写入总计一次。 |
| 普通输入 → 权限守卫 → 原生写入 | 组合绑定检查时丢失了发起成员身份和异步写前检查。修复后两个检查均可到达实际写入边界。 | 另以显式 `/steer`、`/queue` 各测四种握手时序。两组权限稳定的对照各写一次，六组在握手时降权、撤销准入或停账号的用例均未写入。 |
| 四个渠道的引用 → 消息分派 | 引用内的命令属于资料。 | 八种引用容器分别携带 `/stop`、`/approve A1` 经实际解码和 Bridge 进入原轮次。共 16 种组合，未触发对应控制操作。微信 16 组、企业微信 14 组、飞书 10 组亦经过各自的解码或父消息读取进入 Bridge。合计 56 组，各介入一次。微信语音转写、企业微信混排、飞书禁止跨群读取和纯媒体/缺失正文均有专门断言。 |
| 重启 → 历史同步 → 原卡 | 核对历史边界、活动状态和终态事件的先后顺序。 | 重启后强制同步到一千个此前未见的旧轮次，旧结果投递为零。新的完成结果只投递一次。两种顺序下的旁路中断事件均未覆盖原生完成，仍属活动状态的轮次保持待确认。 |
| 远程共享编辑器 → 主机子进程 → 中文正文 | 原实现单独解码每次管道读取，汉字的字节跨块时出现替换字符。改用流式 UTF-8 解码。 | 让子进程分两次交付「共」的字节，中间等待主进程回执。修复前读到「���享目录 📁」，修复后完整读回「共享目录 📁」。 |
| 多根 Web IDE → 主机就绪回执 | 同样的分块问题还会破坏启动回执中的中文工作区路径。IDE 主机传输现使用流式解码。 | 子进程在「工」的第一个字节后等待主进程处理 profile 事件。原实现把「工作区」读为「���作区」；修复后读到完整路径。 |

下载附件还发现了一处资源泄漏。测试主机已经返回暂存目录，文件在 Connector 打开前消失，此时尚无下载句柄负责清理。修改前副本清理函数调用 0 次，修改后调用 1 次，并确认目录已删除，调用方仍收到原始文件缺失错误。

群成员解绑帮助也补了一条直接对照。旧的单命令帮助一律写“当前聊天”，读者无法判断解绑是否影响其他群成员。现在 `/help /unbind` 同时说明成员独立绑定及全群共用绑定的作用范围；命令帮助回归和双人群回调集成验收分别检查措辞与真实行为。

## 第三层 · 函数、代码和回归

Web IDE 管理页另有两个已复现的时序问题。点击保存端口 8790 后，在 Profile 校验返回前改成 8791，旧代码会提交 8791。导入配置时把字号手动改成 22，迟到的文件又会将其覆盖为 14。修复后，提交保留点击时的端口、启用状态和链接授权人，后续输入保留为草稿。慢导入只载入期间未编辑的字段。管理页测试文件的 16 项用例均已通过。

源代码和测试中的对应位置登记在[函数契约](../architecture/function-contracts.jsonl)。显式介入由 `session-control.ts` 管理提交记录，`app-server-runner.ts` 核实原生回执，`turn-submission.ts` 保留输入权限检查。查阅与修复前，先用针对性的反例确认原有行为会失败，再检查修复后的成功、异常和重复提交。授权时序覆盖了实际协议客户端通过标准输入输出和测试服务握手；真实隔离的 Codex 核心另有五项专项通过。

Gateway 最终工作树启用了本机真实 Codex、Chrome、code-server 和 GitLens，4,034 项通过，0 项失败，5 项按环境跳过。前一次普通全跑为 4,022 项通过、7 项跳过。期间一次调用填错了本机 Codex 路径，产生 94 项失败；改用已安装的 0.169.1 可执行文件后重新跑完整套，以上为纠正后的结果。各次运行的启用环境和测试枚举不同，不能直接相减作为新增用例数。Taskboard 另有 591 条命名用例通过，测试运行器另计 5 个辅助模块。TypeScript 类型检查和 Git 差异格式检查均通过。

第一次全跑发现四项测试的服务握手分支需要修正。同次运行还出现过一次更新重启检查失败，单文件与后续完整运行均通过，首次失败的具体原因尚未定位。另两处夹具分别纠正了过短的桌面连接等待以及 Chrome 退出与临时目录清理的竞争。真实工作台首次发现两个 Git 根目录超过原测试的 10 秒等候，单独把该发现条件的期限改为 30 秒；重新运行及最终全量均通过。
