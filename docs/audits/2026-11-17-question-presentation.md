# 问题类型与关闭原因增量检查

用户要求问题卡显示同步/异步，并把含糊的失效提示改成具体原因。此前异步原生模块已有固定原因日志，但结果回调只传结果，Gateway 无法区分轮次结束与其他入口已答。本次补齐原因传递和展示，保持原提问寿命、轮次执行、答案提交及重连策略。

## 四层检查

1. **架构**：原生适配层拥有原因证据；Connector 透明转发；Gateway 只持久记录并展示。原因是结果回调的可选第三参数，不进入请求对象或身份键，避免 Peer 两条路径按原对象匹配失败。execution/nativeAdapter minor=1，原两参数处理器和缺原因的旧 Connector 兼容；缺失元数据不能作为已回答或超时证据。
2. **模块与正交组合**：同步/异步、敏感/普通、卡片/文字、13 种已知关闭原因及未知/恶意原因、重启/重复旧回调/跨聊天、断连挂起/最终确认、单消费者/多消费者、执行回调/独立订阅分别核对。扇出只有原生已接受才给其他入口 accepted-elsewhere；提交获选但回执未知使用不同原因，不伪报成功。功能 case 为 INT-02.presentation-1～5，没有提升其他历史 case 的状态。
3. **函数与代码**：逐句核对新增类型解释/原因格式器/枚举解析器、控制器新建及重观测、关闭回执、同卡通知、晚到 answer/skip、绑定撤销、显式到期，以及 Runner 原请求解析/退休方法和异步 report。调用链的显式二参包装逐处补第三参，包括挂起的提交回调、Peer、Fanout、Service、AccountManager 和兼容 Desktop monitor。记录 17 个选定函数合同的当前 SHA/行号；大函数仅核对本次分支及相邻依赖，不声称重读全仓所有行。诊断和 UI 不传递异常正文，秘密问题不新增 IM 作答控件。
4. **静态、配置与文档**：类型检查及差异空白检查；功能合同、原生交互模块、版本合同、session 需求索引和探探教程源码同步。HTTP/Peer 帧/日志版本、既有能力开关、产品包版本及线上配置不变。没有修改审批决策或执行器，也没有向群发送回归消息。

- 定向单元回归：初次 106 项中 8 项失败，均为测试仍按旧 title 位置取状态或新测试误用了卡片 DTO 的 choices 字段。按新展示合同改成末段状态、实际 actionGroups，随后 106 项通过，保留原并发投递/提交断言。
- Peer/版本/相邻回归：首次沙箱无法监听本机测试端口而报 EPERM；获工具隔离执行授权后重跑 50 项，48 通过、2 按原条件跳过，无失败。
