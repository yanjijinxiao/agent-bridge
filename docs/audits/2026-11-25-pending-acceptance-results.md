## 已复现并修复

1. 旧状态中容器类型损坏时，读取会将其转换为空集合并写回。现对 18 个关键容器进行形状检查，重复刷新及冷启动都保留原件。
2. 账号停用后迟到的扫码成功回调会重新拉起监控。现在在账号串行操作内读取已保存的启停状态，重新启用另有阳性对照。
3. 同一项目改名或 Git 根目录重排，会使原 IDE 待批或复用失效。工作区身份比较纳入实际主机和根集合，根列表顺序或显示名更新仍能走原授权。
4. Taskboard 保持历史会话选中时切换项目，旧 FileReader 的结果可能写到新草稿。读取请求现在绑定到当前项目、任务和草稿代次，成功及失败两种回调都做归属检查。
5. 入站附件下载失败时，异常文本可能包含带签名的地址。日志现保留消息关联编号、渠道和有限的故障类别。使用测试标记验证四条渠道路径。
6. 微信回调只含引用编号时，原先会丢掉引用。现在保留合法原编号供同对话缓存核对，无法获取正文时向模型说明缺内容。
7. 飞书等待资源头或读取响应体时缺少统一时限。现在超时会终止本次下载，实际 SDK 测试确认 HTTP 资源连接关闭，取账号凭据请求仍可独立完成。
8. 同一条消息含多个附件时，钉钉、微信和飞书在第二个文件失败后可能留下前一个文件或半截内容。四个渠道现在共享独占创建和本批失败清理，原有文件保留。
9. 同一账号重连后，旧渠道实例上的提问或审批可能将迟到答案交给 Codex。换绑时原问题还可能先显示失效、后又收到确认。现在作答时核对渠道实例及执行代次，并在失效时消费原路由回执。
10. 线程被明确归档后，交互观察器仍订阅并重试。现按原主机线程撤销监听，明确恢复后只订阅一次。
11. 用合成标记复现了旧式日志上下文、ticket 字段和管理接口错误中敏感文本的泄露。修复覆盖结构化事件、旧式日志关联字段和管理通用错误、账号状态和原生中继 stderr。
12. 任务板将读取取消或损坏的成功响应当作空对象，真实管理页内嵌的任务详情可能白屏。现在按原取消返回，缺正文的写入保留结果未知；只有明确无正文的成功响应按协议处理。
13. 任务板显示上一轮已完成、尚在释放旧观察器时，新输入偶尔被误报为仍有任务执行。等待同一轮清理后重读提交记录，下一条只受理一次。
