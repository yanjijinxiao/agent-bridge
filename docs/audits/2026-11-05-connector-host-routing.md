# 单 Connector 多主机路由检查

本次问题：迁移时把连接身份当成了执行主机身份。原生后端本来支持按 hostId 访问本机和远端，Connector 却丢掉 hostId，并对路径使用本机 fs，导致目录遗漏且其他命令可能落在错误主机。

## 四层覆盖

1. 架构：Connector 继续复用原 CodexBridgeBackend；连接入口与目标主机分离，不再要求每个远端运行 Connector。Gateway 不恢复直连执行或另建原生核心。旧逻辑 host、绑定、来源回执保持不变。
2. 模块：主机通道、注册清单、个人/托管授权、目录选择、管理命令、历史/队列/审批回调、文件、共享文本和 IDE。目录分组不授予其他主机权限；固定会话授权不扩展。
3. 函数：穷尽类型检查的 host 参数位置表；通道注册和未知通道拒绝；相同 thread/project ID 的主机隔离；最后写入守卫；文件描述符、哈希、租期和远端 canonical 路径；自定义 CODEX_HOME 的 SSH 配置贯穿文件系统及 IDE 安装。
4. 静态与配置：managedRoutes 支持同一个 node/profile 的多个不同 nativeHostId；拒绝重复目标；保留 grantId。Connector 配置和部署保留原回执目录。README、连接教程、架构/模块合同及新增用例对应更新。未改任务板静态资源，不声称对未改全仓再做逐行审查。

新增回归覆盖一个真实 WebSocket 连接的两个主机、同 ID 不串线、目录及空项目、远端项目新建、历史/执行/重连、个人跨用户拒绝、未知通道拒绝、托管物理身份不可借用、文件端口及 canonical 根范围、非默认 Codex profile 的目标主机配置。现有审批、队列、断线恢复、文件和 IDE 回归同时运行。
