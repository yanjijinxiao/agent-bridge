# 原生加载提示与 IDE 链接分离

用户截图中原生加载点紧贴“打开项目 Web IDE”，容易被误认为 IDE 正在打开。上一轮把短操作页脚放进流式组件，未约束光标所附着的末段，导致位置回归。

现有公共模板只有静态正文与流式正文两个区域；不能通过未绑定字段增加第三组件。本次在原流式页脚后提供独立的任务状态段落：运行时“任务仍在执行”、恢复时“正在恢复原任务”。加载提示仍在卡片底部，不宣称移到顶部独立组件。阶段正文、停止复制框、IDE 链接及原字段布局保留。

## 增量四层检查

1. 架构：原生执行状态仍由 activity 提供，渠道只投影；不改变会话执行、权限、交接或原生任务。未把大段阶段正文塞回流式 API，也未取消原生加载效果。
2. 模块：HTTPS/SDK 共用 activeDingTalkLayout；两类回执缓存不变。运行期间正文刷新不重写页脚；恢复标签真实变化才更新页脚。等待状态与终态沿原静态路径清理加载。
3. 函数：检查 activeDingTalkLayout、initialDingTalkCardData、两种 updateWithRetry 及 normalizeDingTalkCardContent。状态段落位于复制围栏外，不包含链接；1 KiB 预算在生成最终文本后检查、在任何接口写入前拒绝超限。
4. 静态/配置：现有 template ID、order、contentKey、状态 checkpoint 和配置格式未变。更新状态设计、阶段架构、渠道模块、功能 case 与函数记录。没有修改模型正文和持久化用户数据。
