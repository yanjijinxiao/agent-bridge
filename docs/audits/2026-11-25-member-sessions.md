# 同群独立会话与任务卡标题的四层检查

## 本次边界

用户要求同群成员能同时对探探说话，各自续聊自己的会话。两张钉钉截图还要求在原先的进行中、已完成标题之后显示会话和机器。旧账号默认沿用原先的绑定策略。本次验收使用独立的 Gateway 状态目录、独立 Connector 和临时原生 App Server。生产机器人配置和生产用户会话未参与测试。

| 层级 | 检查对象 | 实际核对 |
| --- | --- | --- |
| 整体架构 | 钉钉回调 → 收件日志 → 绑定 → Connector → Codex → 钉钉回执 | 用两名模拟群成员同时提交；真实原生历史分别包含各自输入。最终卡的群号相同，原生会话、卡片编号和定向 @ 分别对应各自成员。 |
| 模块与异常 | 准入、设备选择、自动创建、输入收集、审批、恢复与终态投递 | 单人两条共用一次创建，双人首次并发建两个会话。跨群、私聊、暂时离线、重复回调、显式解绑、模式热切换、重启与旧会话继续分别验证。审批、答题、停止与消息合并不能操作其他成员的会话。 |
| 文件与函数 | 入站地址、创建凭据落盘、原生写前检查、订阅读取来源、各页面的创建／投递回执 | 核对读写者与调用点；新增函数契约关联到 BIND-06、DEL-11。特意让另一人的消息触发后台同步，并让两条订阅指向同一原生线程，验证其中一人的拒绝不会变成另一人的读取成功。 |
| 静态文件与配置 | 账号 schema、管理 API、绑定列表、设置表单、标题投影、用户教程 | 旧账号缺省值、离线设备回显、不支持新建的设备、切换编辑账号后的过期响应均有断言。HTTPS 和 SDK 卡片载荷逐项比较项目符号、代码框、活动提示、IDE 页脚、最终卡和旧版分页恢复。 |

## 检查中实际修正的问题

- 后台同步曾继承触发刷新的成员身份。原生读取现按订阅确定身份；快照缓存也区分个人权限。
- 群级投递回执中的收件群号与内部成员绑定不同。现分别核验两侧身份，再交回对应的持久化进度卡；续卡和合并提醒均经测试。错误成员或错误群号会被拒绝。
- 无成员信息的历史绑定在管理 API 的内存返回值中一度多了空的 member 字段。现仅对群成员绑定输出该字段，原有 HTTP 对照测试通过。
