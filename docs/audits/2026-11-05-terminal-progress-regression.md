# 2026-11-05 结束状态与阶段排版回归

## 证据与原因

用户截图显示上一轮结束后卡片仍“进行中”，并反馈阶段改版丢失列表圆点。原生 rollout 的 task_complete 为北京时间 17:19:43；该轮普通 IM 输入有精确 accepted 回执，结果包含教程附件。Gateway 同会话有两条没有 turnId 的旧队列记录；全局输入回执超时和附件处理前的宽泛队列查询均可能拦住原卡收尾。此前仅补了纯文字结果跳过队列的 case，未覆盖“精确当前回执 + 旧队列超时 + 附件最终答复”。这次不是用户漏操作。

阶段投影器新增历史与实时窗口时直接输出普通段落，绕过原列表包装，导致圆点消失；这是保留原格式要求的回归。

## 四层检查覆盖

1. 架构：执行结束、输入接受、结果权限、渠道送达分别有权威；读不到旧回执不能把已结束任务显示成执行中。核对 AccountManager → ThreadEventHub → ChannelTurnPresentation → ChannelTurnTextStream 与动作日志职责。
2. 模块：精确来源优先；未确认来源继续等待；跨绑定/host/轮次不授予附件权限；新任务不被旧结果阻塞；未确认外部写入不盲重发。
3. 函数：逐段核对 nativeResultAuthority/applyNativeResult，observe/reconcile/finishNow/selectTurn/archiveTerminal/retryPreviousTerminals，setActivity/renderBody，以及 phaseParagraphs/phaseActivity 的列表缩进与字符预算。保留动作原文用于重试，渠道只得到经过剥离和装饰的可见正文。
4. 静态与配置：对照两张用户截图、DingTalk 流式 Markdown 编码、状态文案、复制框和 IDE 页脚；更新模块/功能文档与 case 索引。不修改准入名单、Connector 入口、原生权限或服务生命周期配置。

## 验证

初始定向组 24 项通过，包括原排版图标经 DingTalk 编码、超长阶段分页、异常工具、回执未知不执行附件、错误 host 不授予权限、来源失败后重启/新轮次保留原结果和原卡、精确来源成功时不查询旧队列且重复终态只执行一次。旧版 bfdfe11 的同组 24 项中 19 项通过、5 项失败，能复现缺陷。加入渠道整合检查后，54 项通过；全量 3336 项中 3250 通过、86 项条件跳过、0 失败，类型检查通过。全量首先发现两种通道的缩进空行问题，已去除空展示行并完成回归；上下文整理项的断言同步为用户要求的列表格式。最终补测还覆盖快照省略动作块时仍以持久原文判定来源。

这些测试验证真实编排和渲染组件，渠道与原生响应使用受控端口，不等同于手机实机验收。实际运行时旧卡是否补齐需看渠道回执，不以进程已启动代替。
