# 探探扩大组织准入范围

用户要求从 SQL 引擎扩大到截图指定的 MaxCompute 部门。仅调整探探现有个人准入名单，头头范围不变；没有修改业务代码或扩大管理员、群、Connector、会话角色权限。

使用 dws 正式通讯录查询父部门，核对六个直属子部门及基础架构下四个子部门，共 11 个部门。各叶子均继续核对子部门查询；按部门逐个获取成员，并与一次批量查询结果核对。逐部门共返回 127 条，按 userId 原值去重后为 126 个，与批量查询集合完全一致。概览显示的人数与实际成员列表不同，不据此猜测或补造员工 ID；可见性仍受当前通讯录账号限制。

原探探有 35 个个人授权，其中 34 个在当前部门集合中。本次经受保护的管理 API 逐人新增 92 个，原有 35 个全部保留；最终个人准入总数为 127。旧名单中当前集合外的一项没有因“扩大范围”而自动撤销。

实际回读确认：本次 126 个 ID 全部存在于持久化状态和运行中管理 API；原授权全部保留；绑定及会话角色未变；Gateway 进程未重启，探探账号仍 running。具体成员与逐项变更回执仅保存在运维私有状态目录，不提交到仓库，不向群发送名单。本次没有冒充其他员工发送真实 IM 消息，不能把状态核验称为每位员工已实机登录。

这是一次配置生效，不是新增自动部门同步功能。入职、离职或调动仍需管理员同步名单；撤权使用既有个人撤销入口。教程及模块文档同步此范围与边界。
