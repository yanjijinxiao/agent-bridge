# 探探 Connector 省略 CA 的修复与验证

用户要求：连接探探时不填写 CA 也能成功。原行为已用实际 TLS 握手复现：默认信任返回 DEPTH_ZERO_SELF_SIGNED_CERT；显式提供旧 CA 成功。旧入口使用 2026-11-16 到期的短期自签名测试证书，不能只把该证书藏进客户端后声称长期修复。

## 四层局部检查

1. 架构：信任选择属于 Peer 传输，不改变 Codex 执行器、设备配对、个人准入或浏览器授权。仅固定探探 WSS 入口获得内置 CA，其他 Gateway 保持现有行为。
2. 模块与遗漏：显式 CA 优先；空/错误 CA 文件内容不触发回退；其他地址、端口、协议、路径、查询、片段和用户信息不能继承探探信任。关闭重定向，保持证书链、有效期和服务器地址验证。
3. 文件与函数：完整复核 gateway-trust.ts、transport.ts；核对 index.ts 的配置文件读取及 caFile 省略路径。选择函数返回独立 Buffer，公开证书随 TypeScript 构建进入 dist，私钥不进入源码或制品。函数合同及 PEER-01.3 精确命名测试已补充。
4. 静态与配置：核对公开 CA 指纹、CA 属性、自签名校验、有效期及线上服务证书的 IP；检查教程配置模板无 caFile，保留真实探探 URL。核对两端 daemon 配置、状态目录、原配置与旧发布回退备份。

## 实际部署

探探服务器使用已有 IDETLSManager 在独立 peer-tls 目录准备持久 CA 与服务证书。公开 CA 的 SHA-256 指纹为 9E:3E:CF:DC:BA:F8:3A:D6:22:53:C3:02:CA:B7:51:86:94:91:0F:E3:3D:D7:31:08:F6:4D:8C:72:79:03:30:51，有效至 2031-11-03。服务证书有效至 2027-11-04，IP 为 11.158.199.29；指纹 AC:DF:FC:32:DD:EB:DE:B0:EF:48:DB:34:51:8A:81:D0:A0:14:F0:7B:0D:A5:70:53:7B:81:12:01:57:1B:AF:64。

先准备新发布目录、无 CA 配置和旧文件备份，再切换 TLS 前端并更新 Mac / Linux Connector。Gateway 与 Codex 执行器未重启。Mac launchd 首次 bootstrap 在旧服务退出期间返回 I/O 错误；确认旧服务已退出、plist 有效后再次注册成功。

两端均实际删除 caFile，运行 connector-ca-release-20261104，完成 Gateway 注册并报告 connected。Mac 更新前的 7 个原生执行器进程、Linux 的 2 个原生执行器进程均仍存活。使用构建产物内置 CA 的线上严格 TLS 握手得到 authorized:true，服务指纹与准备文件一致。

这证明实际 Connector 无需 CA 文件即可重连注册，不等同于重新执行所有 IM 场景。没有发送测试聊天、重复提交输入或中断原生任务。公开 CA 只作用于 Connector；同入口浏览器的证书信任仍按浏览器规则处理，未安装任何系统信任。

## 续期与兼容

服务器服务证书续签继续使用此 CA；保持 CA 与地址不变时，用户无需更新信任文件。管理员须在服务证书到期前通过同一证书管理器续期并重新加载 TLS 前端；本轮没有新增定时续期任务。CA 轮换须先更新客户端信任并协调切换，不能静默信任线上下载的陌生证书。

已运行的两端配置已迁移。其他旧 Connector 先更新程序，再删除探探配置中的 caFile；继续显式指定旧 CA 会按该文件校验，不能承诺旧配置自动覆盖。旧发布目录、原配置与旧前端证书仅作回退备份，不分发私钥或真实设备令牌。
