# 移除 Gateway 自建长期记忆

用户要求删除 Gateway 自建记忆；附件收发是既有功能，不是待开发功能。之前“附件或记忆操作未确认”描述的是结果副作用的投递回执，不能解释为功能尚未实现。

## 架构与迁移合同

- 长期记忆由 Codex 管理。Gateway 不提炼、保存、检索或注入偏好，不修改 Codex 的配置、记忆存储或历史会话。
- 删除 `/memory` 及其别名、帮助和管理卡片入口，删除状态中的 `knowledge` / `knowledgeEnabled` 和相关实现。旧账号状态在正常加载迁移时清除这两个退役字段，其他账号状态与独立 llm-wiki 知识库不受影响。
- 旧回复中的 `remember` 字段不再执行，隐藏动作块但继续处理同块的合法附件；未知或错误附件仍按原校验规则拒绝。已进入原生历史/原生队列的旧上下文不重写、不重放。
- 附件动作保留精确输入归属、发送前持久化、回执未知不重发及绑定复核。旧日志的动作序号包含最多三个记忆动作；新实现必须识别这些旧附件回执，不能因移除记忆导致重复发送。

## 四层检查计划与 case

1. 架构：核对 IM、Web、原生队列、完成回调、重启恢复共用边界，确认没有旁路写入/注入。
2. 模块：补旧状态迁移、命令入口移除、旧 remember 与 send 混合输出、纯 remember 完成、发送未知/已完成日志兼容。
3. 文件与函数：逐处核对提示词构建、状态归一化、动作解析、日志键、Bridge/AccountManager 回调；原依赖记忆计数验证的归属/崩溃恢复 case 改为真实附件副作用计数，不能删除原保障。
4. 静态与配置：更新中英文 README、当前架构/模块/功能映射和帮助菜单；历史审计保留当时事实。Codex 权限与原生记忆开关不变。

本文件为此次功能删除的四层增量检查，不声称全代码重新审计完成。

## 实现及验证结果

已删除自建知识模型、状态读写接口、记忆动作、IM/Web/queue 注入及菜单/帮助入口。旧知识字段随账号状态加载迁移移除；旧历史标记只保留展示清理，不重写已接收原生队列或 Codex 历史。原始附件收发、独立 llm-wiki、个人准入及原生权限保持原职责。

最终根回归 3,249 项：3,163 通过、86 条件跳过、0 失败；另以安装的 Codex 原生核心运行 16 个隔离场景，16 通过、0 跳过。12 个真实进程 SIGKILL 恢复场景改为核对附件内容和一次发送；4 个渠道原生队列确认实际模型请求没有记忆指令。完整回归首次出现 6 项旧菜单/日志条数断言失败，更新为删除后的接口及兼容日志合同后重新完整运行通过；早期 sandbox 回归的本机端口 EPERM 不计为产品失败。

验证文件及测试内容散列见 [validation.json](2026-11-04-remove-gateway-memory/validation.json)、[最终根回归](2026-11-04-remove-gateway-memory/final-results.jsonl)、[原生隔离结果](2026-11-04-remove-gateway-memory/native-results.jsonl)。KB-02.1–.4 已加入功能清单；22 个既有函数合同以 AST 对比更新，其中 6 个方法体改变，其余仅位移；新增解析、提示词及附件日志合同见 function-contracts.jsonl。

真实钉钉供应商发送确认丢失后的人工收件核对、手机端下载及系统断电不在本次验收范围内。发送未知仍不自动重发。原生记忆是否开启由 Codex 管理，此次不会修改它的开关。
