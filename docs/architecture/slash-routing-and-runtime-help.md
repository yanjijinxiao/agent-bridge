# 斜杠输入与终端帮助

## 功能合同

用户确认：未注册的 `/xxx` 先给简短文字提示，再按普通消息转发。路径、引用、代码片段和嵌入正文的斜杠不是 Gateway 命令，不给未知命令提示。

1. Gateway 内置名称及别名优先；已安装扩展使用同一注册清单。已注册命令的参数错误、权限不足或运行接口不支持，仍由该命令明确回复，不能降级为终端输入。
2. 未注册名称不创建导航卡、不修改正文；保留空格、换行、附件及原会话目标。提示仅说明按普通消息处理，不声称已接收或已执行。
3. 普通输入仍经过准入、聊天角色、共享范围、绑定代次、合并消息及忙碌策略。未知命令不是绕过这些检查的途径。卡片回调中的过期/未知控制不能变成 agent 输入。
4. 注册查询失败时无法证明输入未注册，不能盲目转发。已经接收或回执不明的输入不重发。原有斜杠收件记录的保守恢复分类保持不变；新的实际输入使用原生/终端输入回执恢复。
5. Herdr `/help` 按会话、输入、访问、工作流、能力分项，覆盖全部注册内置命令及别名、参数和扩展。`/help session` 等分项以及单命令帮助应实际筛选内容。
6. 帮助中的能力说明使用执行端能力描述，区分未适配、需配置和无等价接口。终端画面不称作历史对话，中断不称作任务完成；记录型审批仍指向原请求。Taskboard 未启用时明确说明。

## 模块职责

- `command-text` / `parseCommand`：只解析语法和别名，不推断授权或变更旧回执分类。
- `channel-commands` 的输入分类：用注册清单确定控制与普通输入；明显路径无需查询扩展，合法扩展别名优先于未知名称提示。
- `BridgeService`：控制分支与普通输入共用原有权限、绑定和交接边界；未知名称只增加文字提示。共享访问者不能借扩展命令扩大授权。
- `runtime-command-policy`：实际操作的目标与能力判定。
- `runtime-help`：按同一命令清单和能力判定生成帮助；不另建执行逻辑。

## 四层核验范围

本次是针对上述功能的增量检查，不宣称全仓逐行审查完成。

- 架构：命令注册、执行器、权限与恢复责任互不替代。
- 模块：Codex 与 Herdr App/TUI、已绑定/未绑定、共享访问与角色、扩展查询异常、合并/忙碌处理。
- 函数与代码：精确文本、内置/扩展别名、路径/引文误判、失效回调、通知后的异步绑定变化、回执去重。
- 静态与配置：两个教程、兼容性表、模块说明及帮助文本与实际行为一致；不新增连接参数或执行器配置。
