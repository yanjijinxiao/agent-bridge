# 问题类型与关闭原因

## 用户可观察行为

问题卡在普通字号标题标明「同步提问」或「异步提问」，正文补充执行方式。同步表示当前提问步骤等待回答；异步表示当前轮次仍可继续推进。二者不是操作审批，未回答不代表同意。新请求的旧版省略 kind 按既有同步合同处理；未重新观察的历史记录缺少类型时标为「类型未记录」，不从问题内容或选项猜测。

关闭提示按实际来源说明原因：原轮次结束、切换到其他轮次、问题被替换、完整状态中问题已移除、原生已在其他入口记录回答、提交前来源改变、观察/连接失效、明确超时。旧版本没有提供原因时直说「未记录具体原因」，不再混写「已失效或已在 Codex 中处理」。同一原因也用于旧卡更新和再次使用 /answer、/skip 的文字响应。

本次只改呈现与原因元数据传递，不延长提问生命周期、不改原轮次结束时的关闭规则、不自动答复/跳过/重发，不借原因字段改变授权、请求身份或执行器。

## 模块与兼容

- 原生适配层给已有结果通知附加可选第三参数 reason（固定枚举），请求对象和既有结果枚举保持不变。异步原因沿用原生日志中的语义；同步路径仅传确知的原因。
- Connector、执行回调、独立交互订阅、交互扇出和 AccountManager 透明转递该参数。原审批/问题的身份匹配仍使用原对象，不把展示元数据塞进身份键。
- Gateway 验证固定枚举、将原因与原问题一同持久化，再统一生成状态卡/文字；未知值不回显上游原文。旧记录无原因时保守呈现，不自动改写历史或补发旧通知。
- 可选回调参数是 execution/nativeAdapter 的兼容 minor 扩展；旧 Connector 省略参数仍可用，新 Connector 对旧 Gateway 的既有两参数处理器不改变原请求匹配。
