# 阶段成果与实时活动

本次需求来自 2026-11-05 的阶段展示截图及随后“已结束仍进行中、原图标丢失”的回归反馈。红框中的公开 commentary 是按时间保留的阶段记录；蓝框中的公开思考摘要和工具状态是有界的实时活动。两者不能共用一个滚动窗口，也不能重复展示同一段 commentary。

## 职责与状态

- 原生适配器提供 commentary、公开摘要与工具回执，不把原始推理或命令参数送到卡片。
- 跟随轮询的 summary 轮次视图仅用于定位轮次，不能作为完整 commentary。当前活动轮另外用 limit=1、itemsView=full 补读，按精确 turn ID 核验后只投影公开消息；运行状态在全部读取后复核。补读失败、返回摘要或 head 已换轮时保留原卡阶段，不向当前卡拼接其他轮次正文。
- rollout 监听的三种 commentary 记录均保留完整正文，不在事件入口截为 600 字符；长正文由阶段展示按字节预算切段。公开思考摘要与工具窗口仍有界。
- 阶段投影器保留公开说明。下一段说明到达时，将上一阶段工具活动收成计数小结，清空实时窗口；小结只描述观察到的活动，不推断任务成功。
- ChannelTurnTextStream 保存阶段记录、实时窗口和旧版兼容字段，重启恢复同一张卡。
- ChannelTurnPresentation 按渠道 UTF-8 字节预算切段。旧卡保存本段说明和活动小结；新卡继续同一个原生任务。切段意图、新旧实例先持久化再投递，旧卡失败不阻止新卡，不重发任务输入。
- 卡片的状态条、停止命令复制框、项目 IDE 页脚沿用既有展示边界。历史阶段卡结束 loading 并移除停止控件，保留 IDE 入口。
- 会话从 systemError 恢复为空闲是连接/会话状态恢复，不能用任务“已完成”表示；原失败轮次保持失败。

## 边界与验收

检查连续多段说明、工具刷屏、重复快照、异常工具、无工具阶段、长中文/emoji/单段超长、重启、切段写入失败与丢失创建回执。确认各阶段说明没有被窗口淘汰、动态区有界、每个实例和最终结果归属稳定，复制框与 IDE 页脚仍存在。测试不代替钉钉手机实机显示验收。

## 原有排版与结束状态

阶段说明、阶段工具小结、实时思考和工具记录都保留列表圆点；多行内容缩进到所属列表项。工具沿用原图标（✏️、🔌、❌ 等），公开摘要用 💭，工具计数小结用 🛠️。小结中的“工具完成”不等于整体任务成功。此约束同时检查 Markdown 源及 DingTalk 的最终单段渲染。

原生执行终态与结果投递完成是两个事实。已加载持有者确认精确轮次结束后，若来源/附件投递暂不可核对，原卡显示“任务已结束，结果待同步”，移除停止控件并保留 IDE。当前输入的精确回执优先于同线程未解决的历史队列记录；只有缺少当前权威证据时才补查旧队列。核对失败不会重发输入或放宽跨主机、跨会话、跨群的附件权限。

Hub 在结果动作前持久化原始最终答复；来源校验成功后才将可见正文/IDE 保存为投递正文。新轮次开始时，旧原始结果和旧卡实例一起归档，后续通过同一个动作日志继续投递，不能因剥离动作块而丢附件，也不能把旧结果写进新卡。详情见[终态与排版回归记录](../audits/2026-11-05-terminal-progress-regression.md)。

## 钉钉模板区域与更新边界

现有公共模板绑定静态 staticMsgContent 和流式 contentKey 两个不同组件，不能按普通字段等同处理。完整状态、阶段成果和滚动活动写 staticMsgContent；短小、低频变化的停止复制框与 IDE 页脚通过流式接口初始化，之后正文变化不重发页脚。顺序固定为静态正文、流式页脚，原生加载反馈保留。每个页脚帧不超过 1 KiB；阶段成果仍按完整卡片预算换卡。

普通 PUT 写流式键虽然可被服务端消息接口读回，但客户端不显示；新增 progressContent 也不被模板绑定。这两种候选均已否定。正式适配需分别保存普通字段回执和页脚流式回执，创建不等于页脚已渲染，失败不推进对应缓存。已在同一张获准测试卡上用桌面钉钉确认正文结束标记、第二次仅正文更新和唯一复制框/链接；不能替代手机验收。

加载提示由流式组件末尾承载。DEL-09.7 在页脚后增加独立任务状态段落，运行时为“任务仍在执行”、恢复时为“正在恢复原任务”，避免加载点贴在 IDE 链接后。它属于渠道展示，不写入原生事实、复制值或最终结果；合计仍受 1 KiB 限制。此方案保持现有两区模板，提示位置仍在底部，未声称增加顶部独立加载组件。详见[位置回归记录](../audits/2026-11-06-loading-position.md)。
