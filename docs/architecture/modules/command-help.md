# 命令帮助模块

## 职责与事实所有者

这是只读的功能发现及说明模块。运行时仍由原处理器鉴权、解析参数、选择原资源并执行；帮助可见性不授予权限，不缓存模型设置，不提交输入，不订阅会话。功能合同为 [斜杠输入与帮助](../slash-routing-and-runtime-help.md)，回归映射为 CTRL-05.help-1～help-8。

`channel-command-registry.ts` 是名称、兼容别名与帮助元数据的唯一清单。每个定义包含所属分项、详细语法、说明、可选常用摘要、能力提示和只读导航。终端差异只覆盖确实不同的语义，例如新建会启动程序、history 是画面、stream 是有界终端窗口；不复制整套目录。

## 调用与函数合同

| 函数/调用者 | 输入与输出 | 边界 |
| --- | --- | --- |
| `selectCommandHelp` | 主题 → 首页、完整、分项、单命令选择 | 大小写/首尾空白归一化；别名用同一登记；`session` 为分项，`/session` 或 `command session` 为单命令；未知主题给导航 |
| `commandHelpRestriction` | 定义及能力/配置 → 不可用说明或空 | 复用 `runtimeCommandRestriction`、原生能力和 `requiredModeForCommand`；区分未适配、需配置、无接口；不调用 RPC |
| `commandHelpText` | 已过滤扩展、主题、上下文 → 阅读正文 | 首页仅常用且可用；分项不列兼容顶级入口，记录控制保留；完整及单命令保留限制；参数模板不生成复制框 |
| `commandHelpChoices` | 同一主题/上下文 → 卡片按钮 | 与正文共用选择器；仅设备、项目、目录、状态、IDE 及帮助导航，不执行新建/中断/计划切换 |
| `channelHelpText` / `runtimeHelp` | 原生或运行描述 → 共享格式器 | 兼容调用入口；不持有第二套帮助实现 |
| `BridgeService.commandHelpContext` | 当前聊天 → 已有模式、Taskboard、知识库及能力元数据 | 不更改 Connector、项目、绑定、角色或原生设置，不探测写入者 |
| `createMainMenuCard` | 正文及已筛选按钮 → 渠道卡片 | 原生卡片及文字 fallback 内容一致；实际可发送的导航在渠道层形成复制控件 |

## 正交性与异常处理

- Codex App/CLI 同一入口，Herdr App/TUI 共用帮助层。上下文来自实际目标运行描述，不从设备名称猜后端。未绑定时沿用现有目录选择路由。
- 所需模式、Taskboard、项目知识库及原生能力独立筛选。当前不支持不等于注销命令；完整参考、直接查询与原执行拒绝仍可用。
- `/approve`、`/reject`、`/answer`、`/skip`、`/intervene` 和 `/queue list|cancel` 的记录归属不因帮助筛选改变。当前后端不能接收新队列输入时，分项仍说明旧回执的处理入口。
- `/follow` 是跟随/同步，`/stream` 是展示；`/access`、`/role`、`/share` 的准入范围各自保留。IDE 直达和个人浏览器确认两种配置不被帮助修改。
- 原生观察能力不可用时，跟随和过程展示的状态查看、关闭及恢复本地默认仍能在分项发现；只标明开启条件，不能整条隐藏这些本地操作。
- 注册命令及别名仍是保留字。扩展别名不能覆盖内置帮助；已注册命令的能力或参数错误不转发给 agent。清理说明不会新增 `/bind`、`/resume`、`/memory`。
- 单命令帮助既能解释失效功能，也能指明恢复条件；查询帮助不会切换工作模式。完整帮助较长是显式选择，不按首页长度截断。

## 回归与限制

`test/channel-help.test.ts` 覆盖首页容量/内容、完整清单/兼容、主题冲突、配置筛选、两种 Herdr 能力和旧记录、扩展冲突及独立控制。原渠道、原生路由、解绑、新建、控制和协议替身测试继续核对业务未改变。

本次不增加自动判断用户是否“需要”某项功能，不以展示层代替权限检查。实际平台客户端视觉效果及线上部署不能由字符串/卡片替身测试推定。
