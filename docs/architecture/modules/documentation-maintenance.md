# 文档、教程与需求变更的维护职责

本模块管理需求与证据之间的对应关系，不参与 Gateway 的接收、执行或发布门禁。历史要求及后续取消从[session 索引](../session-requirements.md)查找；审查方法见[四层检查](audit-method.md)。

## 变更先落到正确的文档

1. 先写用户可观察行为、影响范围、旧行为如何迁移或退休；纠正早期要求时明确哪个决定被取代。
2. 功能合同说明正常和异常结果；模块文档说明事实源、状态写入者、跨模块等待与失败归属；注释解释实现必须守住的原因。注释和文档不能互相代替。
3. case 清单关联精确测试名、来源版本、反例/正常对照、已验范围和未验范围。没有直接 case 时如实记缺口，不能只给一个测试文件名就声称覆盖。
4. 按改变的调用链更新函数记录和逐行证据；不改未重读函数的 hash。旧报告保持历史身份，当前入口中的旧结论直接纠正，不能在底部追加新段落留下两种相反说法。
5. README、帮助、设置页面、教程和管理说明使用相同命令及能力边界。发布、npm、实际运行制品分开核对；文档提交不是运行部署。

通用 Gateway/Codex 清单与 Herdr 清单由[统一入口](../session-requirements.md)索引，各自保留状态及 schema。共用权限、消息交接、卡片、附件、IDE 和管理功能不能在新增后端时整块禁用。后端缺某个原生操作时，只限制相应子操作并说明原因。

## 教程合同

- 探探教程面向使用共享 Gateway 的人，给出管理员确认的实际连接地址和网络条件。通用 README 可用示例，不能因此删去专用教程中需要用户使用的地址。
- 每个必填项说明含义、取得方式、是否能直接使用示例；可选项说明何时需要。设备凭据由程序管理，不要求用户把秘密复制进群聊。
- 按准备环境、连接/配对、选择资源、发送任务、控制与审批、文件/共享、Web IDE、群聊与权限、排错及管理员说明组织。Codex 和 Herdr 采用可对照结构，但能力描述须符合各自真实接口。
- 操作教程讲使用方法和功能，不固定过期 Git 提交，不堆发布流水；兼容版本、部署记录和测试证据链接到维护文档。
- 用户明确要求发送教程时，交付可用 Markdown 附件；通过 Bridge 发送本地文件使用其附件动作，不以本地 Markdown 路径冒充附件。
- 用户要求更新指定语雀文档时，以本地已核对教程为来源，核对目标文档并记录同步结果；不能因为更新了仓库就宣称语雀也已同步。历史文档复核不代表新的线上发布，实际操作另留发行记录。
- 探探现有在线页面是 Codex 与 Herdr 两份教程的合并稿。更新前核对原结构，分别使用 tantan-connector-guide.md 和 herdr-connector-guide.md，保留两大部分与统一标题；仅调整围栏外的标题层级，并把仓库相对链接转成在线可访问的绝对链接。不能用其中单篇覆盖整页。更新后读回确认两部分、关键命令及链接，再报告同步成功；仓库两份教程继续独立维护。

## 正交性与验收

检查后端（Codex CLI/App、Herdr TUI/App）、连接/主机、渠道、身份/聊天、原生能力、输入/执行/投递状态、重启/断连、IM/Web/IDE 入口的相互影响。列出实际测试的交叉组合，不把各单维度通过拼成未跑过的笛卡尔积。

对新增后端保留 Codex CLI/App 的回归；对新权限或目录选择保留其他人/群/设备的反例；对卡片变化保留审批、补充输入、分页、结束、重连与 IDE/复制区。真实探探回执与隔离协议替身分别记载。

手机只用于需要该客户端才能判断的呈现/输入问题，不作为通用 IM 业务和浏览器功能的默认完成前提；普通浏览器可实测的流程应直接验证。未测手机画面不能改成已通过，也不能用于无限延期已有任务。
