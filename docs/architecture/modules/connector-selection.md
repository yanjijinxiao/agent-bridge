# 当前 Connector 与目录范围

当前 Connector 决定这个人在当前聊天查询哪台设备的目录。Gateway 按账号、实际聊天和发言人保存所选 hostId，PeerRegistry 校验设备授权。普通输入使用已有绑定的 host 和 thread。群内可以共用一条绑定，也可以按成员分别绑定。

未绑定私聊或群成员的首条普通消息优先使用本人在当前聊天选定的 Connector，未选设备才使用账号配置的默认设备。全群共用绑定始终使用账号默认设备。由目标 Connector 的 `onUnbound` 策略决定是否新建。专供首次对话的设备只向所属绑定提供会话操作。详见[群成员独立会话](../member-sessions.md)。

## 命令合同

- `/connect` 显示当前聊天本人已授权设备、当前选择及在线状态，并提供切换按钮和 C 编号；不改变群绑定。
- `/connect use C2` 使用最新设备列表的稳定身份。按钮附带列表版本；过期、旧版本或已失效授权拒绝，不能按变化后的数组位置选另一台。
- `/connect use local` 选择管理员已配置且本人有权访问的本机 Connector。设备未配置时，命令会提示改选已连接设备。
- `/connect 配对码` 保持原有设备确认过程，成功后记录该设备为当前目录来源。
- `/sessions`、搜索、无项目筛选和 `/project` 使用当前 Connector 的所有已授权目标主机；一个 Connector 只显示一个设备选项，展开后的会话/项目继续保留各自 hostId。`/sessions all` 显式聚合可访问来源；`/sessions --host ...` 仅临时查询，翻页沿用快照，不改变默认选择。
- IM 的 `/leave` 和 `/unbind` 将本人的设备选择与会话绑定一次性重置，旧设备按钮与目录查询失效。已重置时，普通消息使用账号的默认 Connector。浏览目录优先使用有目录权限的默认设备；专用开聊设备只用于会话，浏览其他已授权目录不会把它替换成开聊设备。
- 初次使用且没有账号默认设备和个人偏好时，唯一已授权设备自动选中并持久化；多设备要求 `/connect` 选择；没有设备保持原有本地目录行为。已保存设备离线或撤权时保留偏好并明确报错，不回退到其他设备。
- `/new --standalone` 在当前 Connector 创建；`/new` 不得在切换设备后沿用旧设备的项目；显式项目选择也限当前目录范围。原生创建、审批、回执仍走同一后端接口。

## 状态与并发

`/status` 和别名 `/where` 使用现有会话绑定。Connector 离线时，Gateway 从本机读取绑定和收件箱计数，把运行状态标为待确认。设备在线时，Codex 保留原生诊断，Herdr 保留终端状态。读取结束时再次核对绑定和查看权限。

`RuntimeStateStore.leaveConversation` 在一次状态文件写入中解除绑定、移除设备偏好并记录本人的重置代次。旧版本保存的偏好可由同一个命令清除。账号默认设备热更新时，旧目录分页和按旧默认发起的在途查询失效。

目录选择与原设备断连可以同时发生。`/sessions` 读取所选设备；如果它离线，回复会给出 `/connect` 导航。`/session R编号` 和 `/session 会话ID --host 主机ID` 由目录处理器核对目标与权限，不向旧绑定请求能力描述。`/session new` 仍走所选设备，`/session rename|close` 仍走原绑定。

RuntimeStateStore 保存偏好且不改 activeSessionIds/activeProjectIds。Bridge 的设备快照只保存稳定身份，不持有授权。切换使该用户当前聊天的项目/会话列表失效，异步查询及创建在应用结果前重新核对选择代次，避免 A→B→A 返回旧结果。每次目录操作及使用缓存时重检权限；已有绑定的普通输入和后台任务仍沿用原目标。尚未绑定时的创建回执保存所选设备和选择代次，并在原生创建前后复核。

设备在线状态由 Registry 的实际连接提供，名称不作为身份，同名设备展示独立编号及主机身份。首次迁移仅增加空偏好字段，不重写绑定、授权或 Codex 配置。

多主机连接的合同和文件/IDE 边界见 [Connector 主机路由](../connector-host-routing.md)。旧目标主机偏好可归到原连接入口，既有执行绑定不变；显式 --host 查询仍只查指定目标。个人共享授权只能看到获准的目标，不能因为分组获得父入口或相邻主机权限。
